# ADR0045：完整接入 N14 参考提供器，保持输入权限与读出可辨

日期：2026-10-19。状态：接口／CPU 验证完成，GPU 端到端待验收。
承接 ADR0042–0044；保留 ADR0037 的主次策略，不重开 N15/N16 的参数搜索。

## 决策

N14 不能通过继续读取历史 `typed_readout.pt` 来冒充新的完整推理。
统一入口先按现有源视图配方生成本次 initializer，再执行以下顺序：

原始正负涂画 → 参考图 DINO 对应 → 两个 SAM 参考候选 → 源端整候选选择
→ 相同两帧实例传播 → 原生射线算子 → 既有公共 Huber 响应重建。

`PipelineConfig.reference_completion` 是显式扩展，默认关闭。
`quality` 是已保留的次要质量方案，`feasible` 仍是历史 N14 主策略；每个配方的八个任务
使用同一个策略，不做场景择优。原生分辨率、提示点预算、阈值、步数和几何后端固定。

## 输入与输出边界

- 输入配置单独绑定参考 RGB、既有非 GT 参考掩码、原始正负涂画、目标 RGB、教师权重
  和几何拟合记录。目标视图不得进入 source-only initializer 的建场、源传播或几何验证帧。
- 初始化阶段保留原来的正提示／源视图协议；N14 阶段才启用声明的负涂画与目标 RGB。
  两阶段的权限不能混写成“v10 原本已经使用这些输入”。
- 提供器不读取 evaluation JSON、GT 图像或历史研究预测。配置准备可读取评价帧元数据，
  但不读取 GT 像素。CPU 追溯审计读取历史 decoder 记录核对源端策略，不是新推理。
- N14 更新的是连续语义响应，返回实际三维元素值；不是把直接二维图像当作三维输出。
  既有独立选集保持原样并明确标记来源，不能拿它充当 N14 优化后的选集。
- 评分使用真实输入权限；直接图像响应和三维响应分开报告，两套既有 GT 口径分开报告。
  不将 v10/N14 跨输入差值归因于公共核心或 DINO。

## 验证关卡

两套 31 任务配方保留其他 23 个任务；对源端提示、选择和核函数做 CPU 检查。
规范 worker 与历史 N14 的主函数 AST 一致，RGB 预处理和渲染式保持一致。
这些检查不能替代真实 DINO/SAM、GPU 渲染和最终指标验收。

先在固定代表任务做端到端检查及实际数组差分，再完成同输入机制对照和冻结五项重评。
当前不晋升默认、不改论文指标，不声称已经重现历史 N14 精度。
