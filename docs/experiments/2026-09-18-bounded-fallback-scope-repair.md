# 备用范围读出的有限语义修正与监督缺口

## 定位

承接深度透明度修复后的两场完整模型。上一轮已确认ramen波浪面条在原生源阈值读出31.14%，进入备用范围后0%；最终精确阈值之前已经丢失。概念不被接受，但范围被接受。

代码中的`native_within_extent`实际概率为`0.5*(structural_binary + native_probability)`。对于有限原生logit，只要元素阈值是0.5，其二值判定就完全由structural_binary决定。它只在范围内/外两个层次分别保留排序，不保留原生决策，无法保护高置信的范围外正证据；2D渲染的混合可能缓和但不能消除该缺陷。

第二个系统问题是训练/部署路径分布不匹配。直接从已有源概念监督取实际备用路径，figurines只有24条有效观测，ramen只有1条且无法形成留出视角验证。大多数训练查询被词法概念接受，开放词汇查询却可能依赖缺乏监督的备用范围。

## 修复与边界

新增显式可选模式`native_bounded_extent`：`native_logit + bound*(2*structural_binary-1)`。范围只提供有限logit修正；原生绝对margin大于bound的正/负判定均不被翻转。已有模式、已接受概念的范围路径、图像与点提示路径不变，不修改任何元素特征/几何/教师/query encoder。范围仍可能改变低margin预测和跨范围排序，因此不是全局语义无损保证。

源侧暂时将概念接受阈值设为2，模拟没有可用词法概念的查询，使其经过实际原生支持范围选择；以同一个源query的2D教师范围检验。最终部署保留原概念阈值，所有parent张量逐项完全不变。该反事实并不等于教师/基础场从未见过此对象，不能声称独立开放词汇验证。

修正强度候选固定为0/0.5/1/2/4，只按前12个源视角的同mask范围去重后宏IoU选择；最后4个源视角仅验收。基础场/范围头已见过这些源图，因此这里是读出控制的留出，非独立family验证。两场均选择4，分别有1402/774条源query-view观测。未按真实benchmark查询选择强度。

## 验证

34项相关测试通过：有限修正保护强margin、弱margin可被修正、零强度还原、非法强度拒绝、行/查询分批一致、已接受概念与图像/点提示不变、旧范围模块回归及准入诊断。

输出：`output/bounded_fallback_repair_20260918/{figurines,ramen}`。候选字段位于各`output/depth_opacity_pipeline_20260918/{scene}/reconstruction/field/bounded_fallback_admission`。第一次直接源备用样本不足的失败记录保留；没有把失败改为成功。两种候选均已完成线上/重放、三类查询及选择集合独立渲染。

## 正向补充对照与完整结果

双向有界修正仍可删除低margin原生正响应。另做同一固定源侧网格的正向控制：`native_logit + bound*structural_binary`。它将范围外视为未知，保持范围外原生值精确不变，范围内只允许有限增加；因此备用路径元素正集合包含原生正集合，不保证真实精度/IoU，也不保证所有已接受概念路径具有该性质。

两场源训练仍选4；源留出IoU达到30.451/38.668%，均优于硬范围和双向有界修正。独立拟合准入模块后再做真实开发评价；不因benchmark类别结果修改强度或阈值。导出脚本`export_positive_fallback_scope.py`已复验两场导出的架构及所有parent张量完全一致。

正向规则将ramen波浪面条从0恢复到30.99%，筷子保持53.94%。但figurines的waldo、带圈鸭子等发生退化，且集合选择整体退化；这是保留原生误检的实际代价，不能把“范围外未知”解释成“原生正例一定正确”。

**结论**：双向有界修正作为两场更稳妥的开发候选保留（文本、AP、所选集合均小幅改善，image/prompt不变），仍未通过四场/跨benchmark晋升。正向补充保留为有效机制反例和研究候选，不取代通用主线，也不按场景/类别拼接最优结果。原硬范围、双向和正向候选的参数/日志均保留。不存在新独立final test或SOTA对比结论。

源侧的完整概率图监督可以批准一个损害所选集合精度的候选，进一步确认输出合约必须进入源侧验收。下一步应在相同源查询上联合检查“原生范围外正响应的可靠性”及“选择集合独立渲染的误检”，只在有可见、对应一致的负证据时压低响应；不能继续用范围未覆盖充当负证据，也不能强保留所有原生正值。已接受概念的整体/部件问题及独立family验证仍未解决。
