# next48：载体交换、集合解码与错误排除

## 本轮要回答什么

附件建议先固定教师与读出，区分几何、有效输入预算、语义写入与范围推断。本轮完成 VALA 官方代码的四场景三组交换；并以两个困难场景的 GT 辅助干预区分“载体不能表达”与“优化了不相容的输出目标”。随后在合法源监督上实现独立集合解码，未新增检测调用、未读取目标 RGB 或标签生成方法预测。

这些是长期反复开发的 LERF 场景，不是新的独立测试集。GT 辅助干预仅用于诊断，和下文 source-only 方法分开。没有新增测试或审计框架。

## 1. 相同 VALA 语义处理，换载体后的差距很大

| 载体/源语义视角 | figurines | ramen | teatime | waldo | 四场均值 |
|---|---:|---:|---:|---:|---:|
| 历史 RGB Gaussians / 全部非标注视角 | 57.526 | 36.885 | 69.121 | 43.884 | 51.854 |
| 历史 RGB Gaussians / 当前源子集 | 55.417 | 37.373 | 66.854 | 38.466 | 49.527 |
| 当前 MoGe Gaussians / 相同源子集 | 37.433 | 18.842 | 52.400 | 32.075 | 35.187 |

指标均为官方 VALA 的直接集合投影 IoU，非概率图 IoU。源子集逐场为 20/25/23/22 个相同帧（产物 arm 名 `rgb20`、`moge20` 的 20 是实验简称，不表示每场都是 20）。使用官方三层 CLIP 缓存、默认鲁棒融合、默认可见性门控、KNN10、0.6 阈值与官方 scorer。未修改官方方法代码；本仓库 wrapper 在场景加载阶段限制训练相机，保留原评估相机。

固定 RGB 载体，增加源语义视角只增加均值 2.327 点，并非每场受益；固定源视角与 VALA 方法，MoGe→历史 RGB 载体增加 14.340 点。这个交换说明，当前载体和可见性/特征归属的组合是重要瓶颈，不能再笼统宣布“几何已经足够好，只差语义”。

**边界：**历史 RGB 几何的训练输入/划分未重新建立；上述不是等几何训练预算比较，也不是从零复现的作者成绩。MoGe 载体导出时保存原中心、旋转、尺度与 opacity；RGB SH 为占位值，语义门控和投影 mask 不依赖其颜色值。这个结果不能归因于 MoGe 深度模型本身，也不能证明所有差距均由纯几何误差造成：VALA 门控与两类载体可能存在不同适配程度。当前官方代码四场 51.854 也不能冒充论文发布的数值。

## 2. GT 辅助诊断：连续语义响应与实体集合有不同目标

固定载体，用标注视角的真值同时拟合和评分。这是有 GT 的可达性干预，没有独立测试意义，更不是理论上界。未将这些参数用于方法预测。

| 场景/载体 | 拟合归一化概率图：2D IoU | 同解直接选元素：投影 IoU | 改为直接拟合集合 alpha：投影 IoU |
|---|---:|---:|---:|
| figurines / MoGe | 73.811 | 43.983 | 67.787 |
| figurines / RGB | 88.867 | 41.831 | 81.116 |
| ramen / MoGe | 58.671 | 34.394 | 50.399 |
| ramen / RGB | 87.744 | 32.993 | 80.077 |

归一化概率图使用完整场景的透射率；移除未选中高斯后，剩余高斯的遮挡与 alpha 累积发生改变。让同一个标量同时拟合两个输出，本身就存在目标冲突。正确的源掩码并不足以保证直接集合选择正确。诊断使用完整载体，不施加当前语义场的 observed 子集限制，因此不是当前部署场的性能上界。

直接 alpha 干预使用 3000 个 query-view 更新、BCE+overlap，概率图干预为 300 步完整多视角逆渲染；预算/损失不同，不能只用这张表精确分配每种优化因素的贡献。但它证明当前 MoGe 载体仍有明显可利用的集合表达空间；同样干预下 RGB 更好，尤其 ramen，载体问题仍独立存在。

## 3. 实际方法：语义响应和集合成员度分开解码

保留 next44 的语义概率 `p` 作为连续查询输出与初始化。独立求解临时集合成员度 `m`，直接渲染 `alpha_i*m_i`，用已存在源 SAM3 掩码的已知区域计算 BCE+overlap。所有几何/基础 opacity、场特征和 query encoder 冻结。部署时用 `m>0.5` 选元素，仍以原 byte>10 的 alpha 投影评估。

这不是训练第二个持久语义场：`m` 是 query-transient 状态。也不把 `m` 称为校准语义概率。独立解码后，直接用 `m` 渲染概率图会退化，必须明确两种输出，不能隐藏该事实。

| 源侧方法 | 连续概率图 IoU（若直接使用此解） | selected IoU |
|---|---:|---:|
| next44 同一个概率阈值选集合 | 53.914 | 37.710 |
| 独立集合解码，60 更新/query | 47.931 | 40.123 |
| 同预算联合概率与集合目标，120 更新/query | 49.621 | 41.586 |
| 独立集合解码，120 更新/query | 37.138 | 42.379 |

60 更新控制已比 next44 高 2.413 点 selected；120 更新的独立目标比同预算 joint 高 0.792 点。不能把全部 4.668 点都归于“解耦”一个因素：损失类型、正则和预算也与旧方法不同。

固定以原 `p` 提供概率图、以新 `m` 提供集合的 typed 输出，实际重跑四场后保持 IoU53.914/AP71.211，selected42.379。这是预先指定的两个输出，不是逐查询/逐场选 GT 最好的分支。`evaluate_scope_dictionary.py` 支持显式 `selection_scores`；GT、阈值、相机、renderer 与 scorer 都不改变。旧输入不含该字段时仍使用旧同一标量路径。

逐场 selected：figurines33.700→37.797；ramen24.052→31.484；teatime51.213→54.301；waldo41.877→45.932。

## 4. 不能用均值掩盖错误排除

无保护的独立 decoder 仍会覆盖原本正确的对象：pikachu 的跨标注视角均值由76.859降至1.313；bag37.071→6.693，coffee54.292→22.467。源检测的完整性问题并未因换 decoder 自动解决。

增加 `semantic_unknown` 控制：源检测为负、但保留的 next44 响应投影超过原0.5决策值时，将该负证据置为 unknown；不添加新正标签。四场 selected为39.670/31.210/54.323/46.038，均值42.810。pikachu恢复到40.838，但仍低于原76.859。因此它只是减少错误排除，不能称为完整性推断已经解决。

该控制的 next44 posterior 已混入运行时检测证据，不能称为独立教师验证。另设 `field_unknown`：仅以冻结 next38 场、未混入本轮 runtime detections 的响应作冲突参考。相同0.5规则、相同120步，四场 selected40.446/30.649/54.002/46.046，均值42.786；pikachu恢复到50.681。它与posterior保护的均值差仅0.025点，不能宣称后者在统计上更优。`field_unknown` 避免用已经混入同一检测结果的posterior验证该检测，是单侧排除控制。即便是离线场，也不是独立真值；它可以保留原错误正例。

### 对称冲突处理与最终研究候选

逐图检查发现，恢复负例之外还存在错误正例：例如对 pikachu 错选相邻物体，对 coffee 错选其他杯子。因此 `field_agreement` 同时要求正证据与冻结 next38 场的源投影正响应相容；正负冲突均置为 unknown，不把场自动当新标签。阈值仍是既有0.5，步数仍120，没有按场景/概念规则。无合格正证据时保留父输出。

| 场景 | next44 selected | 对称冲突处理 + 独立集合解码 | 增益/百分点 |
|---|---:|---:|---:|
| figurines | 33.700 | 42.620 | +8.919 |
| ramen | 24.052 | 29.923 | +5.871 |
| teatime | 51.213 | 55.345 | +4.132 |
| waldo | 41.877 | 46.203 | +4.326 |
| 均值 | 37.710 | **43.523** | **+5.812** |

保留原语义响应、使用上述统一集合解码的 typed 候选，概率图 IoU/AP 为53.914/71.211，均不变。它是统一固定方法，不是按GT混合不同场景赢家。pikachu76.859恢复到76.859，体现没有合格支持时弃权回退，不代表重新学会了该概念。figurines、ramen没有查询均值下降；teatime coffee54.292→42.454，waldo refrigerator96.600→70.366，仍然需要解决。四场平均提升不能掩盖这些失败。

候选保留为开发方案，不改全 benchmark 默认主线。独立完整性判断、是否允许纠正原场错误正例，以及对新场景/查询类型的迁移仍未完成。示例图 `output/vala_exchange_next48/diagnostic_cases.png` 展示单侧控制的回归与收益；`final_cases.png` 展示最终对称控制。它们是评分后诊断，不是方法输入。selected 是二维可见投影评分；优化该指标不证明隐蔽表面或完整物理对象得到正确恢复。

## 5. 源 RGB 载体拟合：有局部作用，但未通过推广

实现只用相同源 RGB 的1500步颜色/opacity/各高斯统一尺度因子拟合，中心和法线不动。没有语义损失、查询或目标标签，先拟合载体，再完整重新执行 VALA 特征提取。对应 ADR0008 的先几何后语义顺序，没有原地替换主线几何或复用旧责任缓存。

figurines37.433→36.443；ramen18.842→24.054。ramen增加5.212点，但figurines退化0.990点。颜色也同时学习，RGB PSNR改善不能单独证明几何改善。该候选不推广；不是通过简单外观拟合就修复了当前载体。

## 6. 投稿意义与下一步

- 本轮比“再加一个教师/传播模块”更明确：载体适配、连续响应到直接集合的目标冲突、错误排除，是三个不同问题。
- 独立集合解码有实际四场收益；仍有严重逐类退化，需要未参与开发的迁移验证，不能仅凭四场均值宣布默认主线或 CVPR-ready。
- 下一步优先检查 false exclusion 的可信程度与源侧负证据资格，同时保持真实集合的损失；不能退回只优化概率图。
- 载体下一步应定位覆盖与跨边界 footprint，保留 MoGe 深度/法线先验，必要时做受几何约束的完整重建。现有RGB交换是诊断，不是授权把历史未知划分的几何当作公平主线。
- 原生语义、几何与两种输出的分离不构成自动成立的新颖性。LESV 已明确区分渲染特征和直接三维检索，并讨论重叠载体；CIF 也讨论 opacity/occupancy 混淆。应围绕“有冲突且不完整的观测下，何时允许排除”形成可验证贡献，而不是宣称首次发现上述问题。

参考原始资料：[LESV](https://arxiv.org/html/2604.01388v1)、[ILGS 官方实现](https://github.com/DCVL-3D/ILGS_release)、[CIF 作者项目页](https://adreamwu.github.io/Consistent-Instance-Field/)。尚未完成它们与当前候选的同证据对比，不声称已有新颖性优先权。

## 复现与结果

- `scripts/research/vala_exchange_next48.py`：三组四场官方代码交换；`--arm moge_fit20 --scene figurines` 运行预拟合载体。
- `scripts/research/fit_moge_carrier_next48.py`：源RGB载体控制。
- `scripts/research/diagnose_carrier_oracle_next48.py`：显式GT辅助诊断；`--subset-steps 3000` 打开直接集合目标。
- `scripts/research/run_set_decoder_next48.py --arm set|set60|joint|semantic_unknown|field_unknown|field_agreement`：源侧解码及原评分器。`typed_readout.pt` 包含原概率与独立集合；`elements.pt` 单独包含集合解，用于暴露其概率图退化。
- `output/vala_exchange_next48/summary.json`：交换、诊断和方法结果分开存储。未改变ScanNet/NVOS，不宣称这些任务本轮有新增收益；UQIS仍暂停。

最终typed输入：`output/set_decoder_next48/typed_agreement/lerf_<scene>/typed_readout.pt`，对应评估位于同目录的`anchored/pipeline_calibrated/evaluation.json`。正常重建运行`field_agreement`后，其目录也生成同合约`typed_readout.pt`；将该文件传给既有evaluator的`--element-results`即使用预先指定的双输出。
