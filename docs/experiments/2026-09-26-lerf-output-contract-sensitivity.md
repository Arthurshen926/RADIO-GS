# 固定地图上的LERF读出差异：4场景208项完整对照

当前49.74%与历史51.74%不是相同的完整读出。这一事实需要纠正比较口径，但不能拿来解释掉当前的方法问题：**给当前同一概率图加入历史30/7算子，IoU反而降到46.83%。** 不更换地图、阈值、源视角、查询编码或元素判断，定位也从81.27%降至77.11%。

实验在读取新诊断结果前注册：`output/lerf_readout_sensitivity_next32/registration.json`。只读取已封存的最终元素概率和冻结几何；在原标注尺寸重新渲染，检查全部208个原始二值PNG哈希与像素完全相同，IoU/定位精确复现。各场先保存全部连续float32预测，再调用现有评分器。禁止目标RGB和教师训练张量访问。

诊断调用原 `evaluate_relevance_maps`：30×30 OpenCV滤波与原图各半、原min–max激活、固定0.5阈值及legacy7掩码处理；定位使用平滑峰值。没有选择逐场或逐query优胜读出，也没有扫描参数。旧开发结果和任何冻结协议均未改动。

**它不能登记成官方协议等价成绩。** 当前只有一个经过校准的元素概率图；冻结Occam协议使用三层原始OpenCLIP相关性、按非GT响应选层。这里没有真实三层，就只评一层，没有把同一张图复制三遍伪装成多尺度，也没有将概率称为原始OpenCLIP相关性。相同后处理算子只是可分责的敏感性分析，不保证完整方法、输入预算或编码器等价。

因此可以得出的结论是：当前的弱项不只是漏加一层图像平滑；历史多粒度语义证据和原生相关性是否更好，仍需在相同几何/输入上重建并比较。不能据这个负向结果取消多尺度研究，也不能把历史分数直接减去当前分数来估计蒸馏损失。

新脚本 `scripts/audits/lerf_readout_sensitivity_next32.py` 独立于冻结入口。沿用的评分器11项测试与本轮排序监督6项测试合计17项通过；其中排序测试不属于本读出诊断，也不重复累计。独立审阅未发现阻断问题。全部22相机、208项完成，无缺失，所有原始二值预测逐像素回放一致。结果与连续预测的哈希链见 `paper/artifacts/lerf_readout_sensitivity_next32.json`。
