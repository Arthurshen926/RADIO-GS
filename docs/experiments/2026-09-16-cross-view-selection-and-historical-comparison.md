# 跨视角选择监督与新旧主线比较

2026-09-16，`codex/surface-object-memory-v4`。本轮完成两场景源侧区域选择训练、概念/区域联合候选控制、三类真实参考查询复核，以及历史预测的评分侧对齐。

## 当前判断

**新候选明显优于 9 月 15 日的低分错误实现，但尚未恢复历史正常性能线。** 本轮源侧跨视角选择监督对错误区域排序有效，但没有带来两个场景的联合改善。保留 `source_extent_rendered_residual96` 为当前开发候选；不按场景选不同赢家，也不覆盖历史性能控制。

“新主线”目前仍是经过局部实测的研究候选，并不是已经通过联合 benchmark 验收、全面替代历史系统的正式方法。下文区分历史记录、评分侧对齐与新方法实测，不把它们混成一个排行榜。

## 历史相比：分三个层次

### 最近低分版本到当前保留候选

相同场景、完整目标观察的文本开发协议（56 / 71 个观察），数值为 IoU / AP，单位 %：

| 版本 | figurines | ramen |
|---|---:|---:|
| 9 月 15 日 grounded_v2，原生空间失真仍存在 | 12.75 / 17.67 | 16.64 / 25.81 |
| 当前保留候选 | **36.51 / 58.97** | **25.10 / 37.84** |

对应参考查询协议，图像 IoU 从 7.13 / 10.44 提高到 33.12 / 13.81；直接注册点提示 IoU 从 4.85 / 9.26 提高到 40.71 / 24.77。这是整个修复序列的进展，不是本轮单个排序器的收益，也不是正式物理实例或独立 3D 点 benchmark。

来源：[源侧监督与真实查询报告](2026-09-15-source-grounded-supervision-and-real-queries.md)、[本轮之前保留候选报告](2026-09-16-routing-extent-and-region-selection.md)。

### 正常历史控制的原记录

9 月 14 日恢复的两个历史路径不同，不应择优混为同一个版本：

| 冷重放控制，原协议 IoU % | figurines | ramen | 四场汇总 |
|---|---:|---:|---:|
| LERF2D retained identity–extent | 42.62 | 37.22 | 39.58（208 观察加权） |
| LERF3D retained latent proposal null，公共 scorer | 58.41 | 30.31 | 43.74（208 观察加权） |

第二行虽名为 LERF3D 路线，此处指标是选择 3D 元素后渲染得到的 2D 掩码 IoU，不是独立三维表面 GT 的 IoU。其四场等权均值为 42.93%，不能与 43.74% 混用。历史 58.89% 四场旧记录是另一个带事后校准的实验，不作为当前有效主线成绩。

这些恢复记录复用了内容绑定的历史 field、teacher/query cache，进行了查询重建/渲染复核；不是本轮从源 RGB 重新训练历史全模型。来源：[历史控制恢复报告](2026-09-14-v4-repair-and-control-recovery.md)、[旧 58.89% 记录审计](2026-08-17-lerf2d-historical-feature-sam3-current-field-audit.md)。

### 本轮新做的评分侧对齐

读取上述已恢复 LERF3D 控制的二值 PNG，校验来源 receipt 和原结果 SHA，用最近邻缩放到当前 480 宽。在**当前相同 GT 多边形栅格、相同 frame/category、相同观察均值**下重新计算：

| 同一 480 宽评分栅格 | figurines IoU | ramen IoU |
|---|---:|---:|
| 历史 retained 预测重评分 | **57.17%** | **30.61%** |
| 当前保留候选 | 36.51% | 25.10% |
| 差距 | −20.67 个百分点 | −5.50 个百分点 |

这补齐了评分侧比较，但**不是完全同信息合约的架构对照**：历史输出经过 selected-only 读出及原先的阈值决策；本轮仅重采样已导出的二值预测，没有以 480 宽重新渲染历史模型、重新训练或统一历史校准过程。两边源输入、容量和构建路径也不同。不能把差距全部归因于某个模块；也不能据此声称新路线已经追平历史。

不从二值历史 PNG 制造可与连续新场 AP 比较的分数。当前只有两场完成这个对齐，不能拿它冒充四场/多 benchmark 新主线结果。

## 方法层面的进展与未解决项

历史有效路径依赖密集场的语义 identity、查询条件 extent 以及回退。近期低分版本中，独立训练的教师解码器与 query 适配器没有可靠绑定，原生空间关系被破坏；区域/对象组织也未保住原范围。

当前路径为冻结 MoGE 几何 → 源区域和多教师证据 → 一个 64 维原生语义前缀 + 32 维结构后缀的元素场 → 原生文本/图像查询及注册结构提示 → 源概念条件的范围读出。已验证的进步是原场状态保护、监督与渲染对齐、真实参考提示提升，以及来源/冷加载约束。原生参数保留不等于全部最终查询能力恢复。

几何方面已有坐标/尺度/法线/近相机遮挡等修复，但历史可视化也记录了新几何的细节和边界损失。没有独立完整 3D GT 证明所有细节都优于历史，不能以“MoGE 高精度”或几何支持率替代该证明。见[几何可视审查](2026-09-15-geometry-visual-review.md)。

当前 RADIO 可选，但所测 checkpoint 的原生文本/图像编码仍绑定 SigLIP；不能把“辅助教师可选”说成任意替换 query encoder 都等价。SAM 本轮提供区域/范围证据，不意味着其所有能力已蒸馏进场。SAM 2D 交互、ScanNet OVS、NVOS 没有在本轮新增完整评估。

## 本轮实际实现：用源侧跨视角结果监督选择

父模型 `source_region_extent96` 已把 260 / 610 个独立源区域范围读入同一个冻结元素场，但只用原生裁剪描述符余弦选区域，真实 IoU 为 34.00 / 18.72%。本轮不更新这些范围头和原场，只训练选择规则：

1. 在每个训练视角，将各候选的元素响应按既有责任矩阵前向渲染。
2. 与该视角已检出的源概念教师掩码比较，得到跨视角范围兼容性。未检出概念的视角是未知，不产生零分负证据。
3. 为候选计算质量先验时，排除它自身的来源视角；在选择训练任务中再排除当前目标源视角，同视角候选也不参与训练选择。
4. 学习 `非负权重 × 原生图文余弦 + 非负权重 × 源跨视角兼容性` 的排序。使用源教师 IoU 的软目标做 listwise 监督，不用评估 GT 或评估 query 词表。
5. 最后一个源视角只留出选择器监督，用该选择 IoU 选 600 步内的 checkpoint。**基础场和范围头此前已看过这些源视角，因此这不是整个模型独立的未见视角验证**，也不是 final test。

源侧选择验证的选中 IoU 从 29.59→35.08%、32.17→51.56%。真实完整文本变为 **34.90 / 24.43%**，说明对失败的独立区域版本有作用，但仍不优于当前保留候选。源侧提升明显大于目标视角提升，不能用源拟合代替真实泛化判断。

进一步保留原先较可靠的概念范围和独立区域一起竞争。两个已训练残差头通过块对角参数组合成同一向量上的全局读出；不引入第二个逐元素场。抽样校验组合前后原候选响应在 1e-6 绝对/1e-5 相对容差内一致。概念候选使用关联源区域原生图像描述符的均值，避免把文本—文本余弦与文本—图像余弦直接放在同一候选评分里。

## 本轮完整真实结果与取舍

完整文本 IoU / AP，单位 %：

| 方法 | figurines | ramen |
|---|---:|---:|
| 当前保留：渲染监督残差概念头 | **36.51 / 58.97** | 25.10 / **37.84** |
| 独立区域，原生余弦选择（上轮） | 34.00 / 58.69 | 18.72 / 31.62 |
| 独立区域，跨视角监督排序（本轮） | 34.90 / 58.61 | 24.43 / 34.90 |
| 概念+区域候选，跨视角监督排序（本轮） | 35.76 / 58.75 | **26.50** / 37.38 |

联合候选中，ramen `egg` 从 49.00→55.74%、`glass of water` 从 40.66→65.21%；但 figurines `old camera` 从 58.84→45.79%，`rubics cube` 从 49.78→48.80%。AP 没有相应联合改善。保留这两个选择实验供后续定位，**不替换当前共同候选，不按场景选赢家**。

三类参考查询已完整复核：两个新选择版本的图像/点提示 observation 均与原候选逐项相等。只改善/改变了文本选择；不能宣传为三种 query 都进步。

## 核心问题的当前边界

已证明：源侧跨视角选择监督可以恢复部分被错误区域选择损失的召回；同时保留粗范围和细范围比直接强换成细区域更合理。

未解决：源概念和教师掩码仍是伪标签，范围兼容性不等于同一物理对象/部件；源侧高兼容候选仍可能在目标视角选错。原概念门控没有改变，它仍限制细粒度/专有名词访问。当前排序只使用源裁剪语义和源掩码兼容性，尚未直接保证所选范围解释了冻结场中的原生查询 identity 响应。

下一步应集中验证“所选区域是否覆盖并解释原生场的查询 identity，且在跨视角保持相同对象范围”，并要求切换候选有可靠收益证据，而不是继续全局放宽门槛或只拟合源侧教师。历史性能控制应继续保留，直到新路线在同信息协议、更多场景及三类查询上实测通过，再讨论替代。
