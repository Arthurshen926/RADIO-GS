# 冲突负例弃权：3D 与渲染监督的完整对照

本轮沿源掩码完整性检查负例监督，完成两个场景、四个修订训练模型和完整真实文本开发评估。**没有取得可采用的整体性能提升，四个模型均不替换主线。** 重要的收窄是：已检测到的跨视角冲突值得处理，但单靠冲突弃权不能解释或解决当前低召回；在正确的渲染监督路径上，它的实际收益也很小。

## 1. 先区分证据冲突与真实错误标签

对每个现有源概念，在源视角内先合并掩码，再用冻结贡献算子提升。若某元素在一个可见源视角 membership > 0.7，在另一个 < 0.1，则记为正负证据冲突。这沿用既有源监督边界，不从 benchmark 调参；极弱可见视角仍可能触发冲突，因此它不是校准后的可靠错误检测器。

上一轮贡献加权 3D 目标中，落在负侧（membership <= 0.5）的概念—元素对：

| 场景 | 负侧对数 | 同时有明确正证据的对数 | 比例 |
|---|---:|---:|---:|
| figurines | 2,679,879 | 61,498 | 2.29% |
| ramen | 9,213,203 | 419,937 | 4.56% |

这是概念—元素对计数，不是独立对象、像素或真值错误率。它证明证据冲突，不能决定哪一侧正确；不同视角共同漏检造成的错误也不一定产生可检测冲突。

## 2. 3D 弃权训练：保留为失败控制

`corroborated_membership_masks` 要求至少两个明确正观察且没有明确负观察，或者至少两个明确负观察且没有明确正观察；其余不作为新的正负标签。缺失观察为未知。多视角一致仍是教师伪证据，不等于独立真值。

实现两臂：仅弃权；弃权并约束未知元素保持父模型响应。固定原生 96D 元素场、query、校准、门控及独立区域头，仅更新概念输出系数。每臂同种子、1200 步、固定最终 checkpoint。

| 全文本开发 IoU / AP，% | figurines | ramen |
|---|---:|---:|
| 保留主线，重跑 | **43.52 / 62.91** | **28.42 / 42.81** |
| 3D 冲突弃权 | 38.41 / 61.27 | 28.09 / 42.12 |
| 3D 弃权 + 未知响应保持 | 39.45 / 61.16 | 28.19 / 42.78 |

两者均拒绝。figurines 41 个概念中有 38 个满足训练条件；ramen 为 54 中 53 个。不能据此直接否定弃权，因为父模型概念头来自源像素渲染监督，改为提升后的 3D 标签同时改变了监督流程。

## 3. 补齐相同输出流程的渲染对照

因此进一步从保留主线直接继续渲染监督，两臂共用相同源视角、同视角掩码并集、渲染贡献、初始化、优化器与 600 步训练：

- `full`：所有原有有效源像素参与教师掩码监督。
- `abstain`：源正像素保持；只有源负像素被**其他源视角**投来的正证据反驳时才弃权，并约束弃权像素响应保持父模型值。

其他视角证据排除当前视角，按可见贡献质量融合，要求投回的支持超过 0.5、membership 超过 0.5。源目标掩码只用于源监督及定位哪些像素原本被当作负例；没有 benchmark 输入。这个条件是实验性冲突定义，不是可靠真值认证。

被屏蔽的查询—负像素对占比为 figurines **1.58%**（30,631 / 1,944,545）、ramen **2.42%**（112,532 / 4,643,276）。这与上一节 3D 对数的分母不同。

训练只更新概念头的线性输出及原有独立概念隐藏块；独立区域头对该隐藏块的权重保持为零。原生场、查询路径、门控、校准和独立区域响应不变。两臂区别同时包括负例弃权和未知响应保持，因此不能单独为这两个作用分配增益。

| 全文本开发 IoU / AP，% | figurines | ramen |
|---|---:|---:|
| 保留主线 | **43.52 / 62.91** | **28.42 / 42.81** |
| 相同渲染监督继续训练 | 40.67 / 62.90 | 28.57 / 43.05 |
| 渲染监督 + 冲突负例弃权 | 40.80 / 62.92 | 28.61 / 43.03 |

弃权相对匹配渲染控制仅增加约 **0.13 / 0.04 IoU 点**，没有重复种子置信区间，不能声称稳定收益。ramen 的小幅进步不能掩盖 figurines 的退化，不按场景挑选模型。两臂均拒绝，保留主线不变。

## 4. 本轮明确解决与未解决的范围

实现了可检查的冲突弃权机制，补齐了错误监督处理与实际渲染输出之间的对照，排除了“只屏蔽当前可检测冲突就能明显恢复召回”这一简单解释。它不是已解决完整负例可靠性，更不是新的高性能主线。

**不再沿这四个控制继续调步数、弃权比例或保持损失权重。** 已检测冲突只是教师不完整的一部分：共同漏检、同名词在不同视角指向不同范围、几何投影错误可能没有显式冲突。后续需直接验证这些源证据的对象范围与对应，不能把本轮统计当作全量错误标签比例，也不能把范围完整性的未验证假设交给更长训练自动修复。

当前全文本开发主线仍为 `exact_render_query_threshold96`，figurines IoU/AP **43.52/62.91**、ramen **28.42/42.81**。本轮没有新增图像、点提示、NVOS、ScanNet OVS 成绩，没有大幅性能提升。
