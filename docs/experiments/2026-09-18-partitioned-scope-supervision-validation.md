# 同名范围分解与隔离视角验证

本轮将同名源监督显式分为相互支持、双向包含、不相容和未知，完成严格四折源视角验证，以及局部弃权、假设容量上限、COLMAP同点标签检查。**没有新的共同性能收益，不替换原完整候选，也不把未通过的分组目标交给范围头重训。**

更明确的结论是：同名范围强制合并确有风险，但现有范围对应证据不足以可靠修复它；全局选一组会损失互补覆盖，取并集会扩张误检。即使事后用留出伪标签挑选本轮分组假设，收益上限也只有约2–3个百分点。ramen还存在绕开MoGe/高斯后仍成立的缓存源监督标签冲突；不能排除预处理造成的标签替换。

## 实现与隔离合约

新增 `scope_correspondence.py`：只读取显式允许的训练视角对；要求双向支持才能直接合并，单向证据不足视为未知。双向父/部件包含关系保留为有向关系，不当作范围相等；明确不相容也不合并。

两种固定分组方式均完成：

- 严格完整连接：组内任意视角对都须互相支持，防止A支持B、B支持C就覆盖A/C的已知矛盾。
- 支持路径连接：未知不等于负证据，允许支持路径连接互补视角，但任何已知包含或不相容关系仍阻止合并；原始未知边保持未知，不冒充已验证身份。

16个源视角按序分成四折，每折用12个决定关系/选范围、4个只用于预测评价。每个视角恰好评估一次。验证视角的掩码、描述符以及以它为任一端点的对应关系均不进入该折的分组、融合或选择。基础几何、既有原生表征和概念清单仍预先存在，因此这是**对应与融合阶段的视角隔离验证**，不是完整pipeline的独立test。

评价全体1466/811个组—视角观测，用完整目标像素分母。输出仍是教师伪掩码一致性，不是人工完整对象真值。

以下均为源侧规则，没有用验证目标挑组。原生匹配使用训练组的原始图像描述符与查询特征；局部选择按各假设在元素上的实际观测质量决定，保留全部训练视角的支持。

训练折内有73.43/47.53%的视角对属于未知。这些比例按折统计，同一视角对会重复出现，不是独立样本比例。直接丢掉非主组，会把未知/互补覆盖一起丢掉；放宽未知连接缓解了损失，但并未获得共同改善。原生语义最相近也不足以决定完整空间范围。

## 局部监督弃权

新增 `scope_vote_abstention.py`，不整幅删除视角，也不无条件取并集。固定强观测条件为至少该元素最大单视角质量的10%且质量>1e-6，明确正负票为概率>0.8/<0.2。所有关系及质量比较均来自当前训练折。

- 对双向确认的包含模式：只在父范围有强正票、部件范围有强负票的位置，移除部件负票的权重，记为未知。
- 对双向不相容：局部正负冲突的双方都弃权，不任意指定哪一侧正确。
- 未知关系不自动触发改写，其他视角及其他位置保留。

| 四折源范围 IoU（%） | figurines | ramen |
|---|---:|---:|
| 原实际证据量融合 | 38.97 | 51.72 |
| 包含关系下负票弃权 | 39.19 | 51.66 |
| 不相容局部冲突双方弃权 | 38.87 | 51.64 |
| 两种弃权合用 | 39.01 | 51.59 |

包含弃权在fig四折均略升，但ramen仅一折改善；没有将小幅局部收益推广成可靠共同修复。所有这些控制保持冻结几何和原生能力，但没有通过进入范围重训的源侧门槛。

## 假设本身够不够

只作诊断，用留出伪标签事后选择本轮训练侧生成的假设，并把原融合输出也作为候选。该真值选择不写入训练或在线策略。

| 源范围 IoU（%） | figurines | ramen |
|---|---:|---:|
| 原融合 | 38.97 | 51.72 |
| 每个概念在一折内固定选一个候选的oracle | 41.91 | 53.97 |
| 每个观测单独选候选的oracle | 43.99 | 57.27 |

前者比原融合只高2.94/2.25个百分点。它仅是**这些固定分组假设及固定响应**的容量上限，不限制未来更准确的对应、局部范围构建或新的教师证据。它也说明，当前失败不能全归因于源侧选择器选错组；假设本身仍有较大范围误差。

## 绕开MoGe和高斯的同点检查

检查严格source-only的COLMAP轨迹；点平均和每次观测的重投影误差均≤2像素。读取缓存保留的原生教师掩码，排除约2个原相机像素的掩码边界，缺少概念检测的视角仍为未知。使用同一track ID建立对应，没有使用MoGe深度或高斯投影。

| 检查覆盖 | figurines | ramen |
|---|---:|---:|
| 至少两次明确观测且至少一次为正的概念—轨迹 | 17 | 7027 |
| 正负冲突的概念—轨迹 | 3 | 651 |
| 上述正样本涉及的不同物理track ID | 3 | 1035 |
| 存在任一概念冲突的不同track ID | 2 | 355 |
| 有正轨迹覆盖的概念 | 15/201 | 77/88 |

ramen在有正观测的概念—轨迹单位上有9.26%的冲突。例：`food that includes eggs` 为69/223，`yellow bowl of food` 为42/114，`piece of wood` 为125/629。说明范围/指代不一致可以在不经过MoGe和高斯的路径上出现，不能全部归因于几何融合。泛化词句也可能指向不同范围；同名不是物理身份或完整范围合约。

fig只有3个不同正track，覆盖不足，**不将3/17外推为全场景的冲突率**。概念—轨迹会因同义词重复计数，不能当成独立物理点。COLMAP身份仍是自动、稀疏且偏纹理区域的对应，不是人工真值；原生教师掩码也经过既有粗掩码去重缓存。没有放宽source-only约束来补足覆盖。

## 原生范围缓存的确定性修复

发现 `ground_source_caption_phrases.py` 原先仅按96×128粗掩码去重：粗掩码相同但原生掩码不同的检测，被统一替换为最高置信度检测的原生范围，多个短语则全部挂到该范围。现改为粗范围和原生范围都精确相同时才合并，输出schema升级为v2并绑定身份实现hash。独立工具函数放在utils，避免SAM环境被迫加载训练/渲染依赖。测试覆盖粗范围碰撞和打包尾部padding。

每场景首个训练视角，按已有别名数选择12个源短语，使用相同SAM权重及推理配置重放；不读取真实查询或标签。

| 原生掩码绑定检查 | figurines | ramen |
|---|---:|---:|
| 接纳检测 | 94 | 18 |
| 旧/新去重后范围数 | 41 / 94 | 10 / 18 |
| 旧/新非原样原生范围绑定数 | 53 / 0 | 8 / 0 |
| 旧替换前后原生IoU最小值 | 98.80% | 99.25% |
| 旧替换前后原生IoU中位数 | 99.72% | 99.69% |

**这是已复现的身份保存错误，但此重放中的差异主要是微小边界变化，不能解释为主要性能瓶颈。** 样本刻意偏向多别名，不能推断全缓存发生率。精确保留也会增加区域数量，后续描述符计算和聚合必须防止重复观测增权。现有完整缓存和场未重建，修复仅对新生成v2缓存生效；不宣称旧模型已获得收益。上述COLMAP检查使用旧缓存，因此其冲突来源包括教师指代差异及预处理，不应全部归因于教师。

## 修复评估分母与验证

初版验证器跳过了“训练折完全没有该概念证据”的目标。已修复生成代码，使这些目标按零预测计为漏检：fig增加8个、ramen增加4个观测。已有报告保持不可变，新增 `full_cohort_report.json` 补齐可证明为零的预测；有训练证据却缺少预测时抛错，不静默填零。上表全部使用修正后的完整分母，各方法对照结论不变。

15项聚焦测试通过：覆盖双向包含、不相容链、未知路径、留出端点隔离、局部弃权、未知与弱观测、无训练证据漏检和已有投影/渲染目标。`verify_partitioned_scope_controls.py` 从训练端点重新生成每折关系与分组，验证组内约束、完整观测集合、各控制相同基线、oracle边界、来源hash和保留模型身份。封存于 `paper/artifacts/partitioned_scope_controls_20260918.json`。

全部已启动控制和诊断已结束。没有启动不满足源侧门槛的完整场重训或新真实查询评估；当前最终开发文本IoU仍为46.20/32.97%，本轮没有最终指标提升的结论。

## 下一步收窄

不能继续默认“同名→同一完整范围”，也不能默认“未知→不相容”。现有分组/弃权机制已具备明确合约，但仍不足以可靠纠正监督。优先补充**源侧可验证的对应及完整范围证据**，尤其是fig缺少可靠正轨迹覆盖；将可确认的完整对象、部件以及指代不明确的教师范围分开记录和验证。对于同点已冲突的源标签，不能仅凭当前教师自一致性决定哪一侧是真实范围，更不能用真实benchmark标签反向选源视角。

下一次重训前需先证明：在未用于对应决策的视角上，新范围证据能提高完整性且不增加外部误检。当前实验不支持直接扩大量、增加范围头容量或继续扫描分组阈值。
