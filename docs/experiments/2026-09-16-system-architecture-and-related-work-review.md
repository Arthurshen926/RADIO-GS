# 当前系统架构、核心瓶颈与相关方法复核

审计日期：2026-09-16。对象是 `codex/surface-object-memory-v4` 当前工作区及保留的 `preserved_source_inventory_20260916/{figurines,ramen}/exact_render_query_threshold96/field.pt`，不是仅凭 HEAD `0ad5dbb` 推断实现。工作区有大量未提交实现；同目录下实验脚本存在不等于对应方法已进入保留模型。本轮为代码、既有实验与原始文献审计，没有训练新模型或产生新的召回成绩。

## 1. 系统级结论

当前方法实际是：冻结 MoGe/COLMAP 几何上的 Gaussian 元素 + 冻结原生语义 64D + 可学习结构 32D + 场景特定文本范围头 + 原生图像读出 + 注册坐标提示亲和读出。

历史独立随机适配器造成的严重原生语义破坏已被当前 native-decoder 路径绕开；但并没有因此解决完整对象召回。主要问题依次是：像素—载体跨视角对应尚未验收；源区域粒度和身份未充分统一就参与融合/监督；最终文本范围读出仍可以覆盖原生语义，图像与提示没有共享同一完整范围推断能力。

“高几何支持率”“教师特征重建较好”“有四教师”“三类 query 都有损失”分别不等于准确对应、最终匹配一致、开放词汇能力保留、三类查询任务定义正确。

## 2. 实际数据与实现路径

| 阶段 | 当前实现 | 重要边界 |
|---|---|---|
| 几何 | MoGe 深度校准至源 COLMAP 坐标，构建表面 Gaussian，语义阶段冻结 | 单视角细节好不证明多视角尺度、遮挡、贡献分布准确 |
| 对应缓存 | 源像素与 Gaussian 的贡献索引和权重；教师常用 96×128 网格 | 低分辨率边界混合会影响提升和监督；480 宽评估无法自动恢复丢失的监督 |
| 语义教师 | SigLIP 原生 1536D 区域裁剪描述；源区域聚合并 SVD 到 64D | 区域 crop 的语义不是区域内每点、每个部件的独立语义 |
| 结构教师 | RADIO、DINO 特征/关系，以及 SAM/SAM3 mask、边界 | SAM 当前主要是结构监督，不是原生 SAM 特征重建；教师不能无对齐地互换 |
| 补充源证据 | 源 RGB/crop 词汇发现、SAM3 grounding、区域与短语原型 | 相同短语不证明物理实例相同，也不证明范围相同 |
| 元素场 | 96D = 冻结语义 64D + 学习结构 32D，语义 decoder 固定 | 保护融合结果也冻结了融合时已经发生的污染与缺失 |
| 训练 | 2D 渲染 membership、3D 部分 membership、教师特征/关系/边界、尺度亲和；后续范围头训练 | native64 冻结后，相关损失不能再改善这部分元素语义；需追踪实际梯度路径 |
| 文本 | native similarity → 概念门控/区域选择 → 范围响应 | 部分路径直接返回范围头，原生语义不具有最终决定权 |
| 图像 | native SigLIP image query → native decoder cosine → 标定 | 保留模型没有使用与文本相同的结构范围补全 |
| 提示 | 注册正负 3D 点 → 元素种子 → 尺度门控结构相似性 | 不等同于已完成任意 SAM 2D 点、框、scribble 协议 |
| 输出 | 元素 sigmoid 响应经冻结 Gaussian 渲染、observed alpha 归一化、有效性判定、阈值 | sigmoid/聚合/阈值顺序不可互换；覆盖率不等于语义准确率 |

figurines/ramen 分别约 274805/362198 个载体，语义 observed 元素 79500/226194。语义源视角为 6/12；这不是全部几何源视角数。当前文本概念头为 41/54，另有 260/610 个区域头，不能继续用早期“全系统仅 14 类”描述它；但这些有限原型也不等于完整开放词汇对象范围。

重点代码：

- `radio_gs/models/element_retrieval_field.py`：查询分支与原生/范围读出。
- `radio_gs/models/grounded_semantic_transfer.py`：概念门控、候选选择与范围头。
- `radio_gs/models/scale_affinity_readout.py`：注册提示种子、尺度亲和。
- `radio_gs/training/source_fusion_initialization.py`：语义初始化和源融合。
- `radio_gs/scripts/train_three_query_field.py`：基础场训练。
- `radio_gs/scripts/evaluate_frozen_field_lerf_labels.py`、`evaluate_real_reference_queries.py`：不同评估协议。

## 3. 历史核心瓶颈是否解决

历史“教师解码头与独立 query 适配器不绑定”的问题不能继续当作当前主线解释。当前 text/image 使用 `cosine(D z_sem, q_native)`，绕开旧随机 query 投影。

同一源证据、几何和融合权重下，未压缩原生融合/当前 64D 原生读出 AP：figurines 59.12/58.49，ramen 31.92/30.97。平均损失 0.63/0.94 个百分点，因此继续加维度缺乏优先依据。个别类仍受损，例如 egg 约 5.82 AP；这个对照也不衡量进入源融合之前的教师能力。

准确结论是：原生空间读取的一个严重错误机制已修复，但源融合的语义质量和最终读出的语义保护尚未解决。native64 保真与最终开放查询正确不是同一个命题。

证据：[压缩与范围读出对照](2026-09-16-native-compression-and-ranked-completion.md)。

## 4. 三个优先级最高的问题

### P0：几何传递不能仅凭覆盖率验收

独立源 COLMAP 轨迹诊断中，ramen 674 点、1684 有向观察对，Gaussian 贡献质心跨视角偏差中位 2.45、p90 6.28 个 128 宽网格像素；量化控制为 0.39/0.74。匹配的旧深度有效子集上，Gaussian/校准 MoGe/量化中位为 2.56/1.92/0.38。

这是承载传递的明确警报，但不是完整贡献分布的精确传递误差，不能全归因于 Gaussian 中心或据此分配最终 IoU 损失。figurines 严格共享点仅 3 个，不能推广上述统计。新纯尺度拟合改善中位、恶化 p90 和均值，已拒绝采用。

应先检查完整贡献分布、深度多峰/前后景混合、高误差视角、法线和遮挡。用全局点 ID 留出验证共同约束典型误差与尾部；样本不足的场景补充覆盖证据。需要修改几何时，全部重建绑定的责任矩阵、教师资产和场，不能复用旧对应。保持 MoGe 细节是目标，但“只差每视角一个尺度”仍是假设。

证据：[源轨迹与尺度审计](2026-09-16-source-track-correspondence-and-scale.md)。

### P1：先混合不一致的对象范围，再学习一致场

整物体、部件、多个同类物体、背景上下文，在当前区域描述与短语 union 中不总是被区分。相同短语只确定语言近似关系，不提供物理身份；某视角未覆盖的地方也不能自动成为可靠反例。

源教师伪目标上的同视角 mask 循环 IoU 为 87.88/93.81，跨视角降为 43.20/43.81，尽管支持率超过 95%。独立轨迹上的 ramen 正共享轨迹—概念对有 9.46% 出现正负冲突；这既非独立点错误率，也不能指明哪一视角正确。

原生区域选择与最佳候选之间还有明显差距：源侧最佳单候选 IoU 72.45/65.65，原生 query 选择只有 52.49/45.16。这是教师伪目标上的诊断，不是 benchmark GT 上限。部分细目标连候选本身都差，不能只优化排序。

正确方向是分别建立物理对应、粒度/包含关系、语义关联。保留 region identity、view、scale、可见性与冲突证据，先在可靠对应和相同粒度上聚合；相邻不等于同对象，不同粒度也不必互为负例。不能简单扩大 union 或继续平均区域特征。

证据：[语义分层与跨视角 mask](2026-09-16-source-semantic-stages-and-cross-view-masks.md)。

### P2：范围候选依然控制二值结果，语义保护不完整

`element_retrieval_field.py` 的补全分支明确计算：

`p_i = 0.5 * (1[i belongs to selected extent] + sigmoid(native_logit_i))`。

对非饱和原生概率，元素是否超过 0.5 几乎完全由选中范围决定。这个设计恢复范围内/外各自的排序，却不保证跨范围排序，更不保证渲染后的像素排序。概念门控接受时甚至直接使用概念范围头。候选选错，冻结 native64 并不能阻止错误输出。

所以它不是普通数值 bug，而是制约 IoU 的明确设计约束。单候选如果不包含目标所需的多个部分/实例，后续校准也不能产生缺失范围。简单多候选 union 曾造成严重误检，不能将其当作已知解。

应在同一套范围假设上明确分开：query 原生语义证据、同尺度结构 membership、可见性/不确定性。文本和图像共享范围推断原则，允许有证据的多区域选择和拒绝；结构不能任意替换语义身份。采用什么组合规则仍须通过源留出和固定开发集验证，不能提前承诺一种公式必然胜出。

## 5. 实现与方法描述的其他不一致

- 当前提示编码仍计算 DINO 前缀，而实际尺度亲和路径只读取最后 6 维正负坐标。可明确简化接口/避免浪费，但没有证据说明这项清理能显著提高 IoU。
- 当前 text/image 实际依赖 SigLIP 原生空间。RADIO 可移除不意味着任意 VFM 已可替换文本/图像 backbone；替换需要相应原生编码/解码与重新验证。
- SAM mask/边界监督不等于使用原生 SAM 特征；四教师数量不能当作能力验收。
- 96D 元素场之外还部署场景特定原型和范围头；不能用“只有一个 96D 场”省略这部分容量和依赖。
- 工作区保留大量历史实验路径，没有一个清晰的单入口完整构建流程。封存 checkpoint 有助于复现，但需要进一步锁定构建 DAG、配置、输入资产、代码和模型身份，避免把失败控制当作最新主线。

本轮没有发现足以证明需要全部架构回滚的新索引错位，也没有证明 pipeline 无 bug。上述确认事实与性能因果推断应分别验收。

## 6. 查询和评估定义

三类 query 可以统一输出元素 membership，但请求的集合不自动相同。文本可能要求同类实例并集；参考图像可能要求该实例或该类别；点/框/scribble 涉及特定实例和粒度。必须显式定义范围，不能以统一余弦形式代替任务定义。

当前 LERF 参考评估从参考图 GT 构建授权 masked crop 或正负点，再检验其他标注视角的类别 union。目标 RGB 不参与当前地图查询。这不是天然非法标签泄漏，但它是特定参考查询协议，不是任意点击/自然图像查询，也不是 NVOS 正式协议；它没有提供独立 3D 真值。

完整文本和参考查询分别使用 56/71 与 35/57 个观察任务，不能直接横比模态均值。反复用于模型选择的两场景是开发集；新主线尚无完整 ScanNet OVS、NVOS 联合验收或独立最终 test。还应加入 absent query、重复实例、部件/整体范围和参考输入扰动测试。

|---|---:|---:|
| 完整文本开发集 | 43.52 / 62.91 | 28.42 / 42.81 |
| 参考图像子集 | 33.12 / 54.52 | 13.81 / 34.21 |

## 7. 相关工作：已有问题与可迁移方案

以下为针对上述机制的代表性原始工作复核，不是完整文献计量综述，也不声称它们解决全部问题。

| 工作 | 对应问题与方法 | 对我们的启示与边界 |
|---|---|---|
| [LangSplat](https://langsplat.github.io/) | 场景自编码器压缩语言特征，SAM 分层语义改善边界 | 紧凑场仍需明确原生语义恢复路径与粒度；不支持任意独立 adapter，也不解决错误几何 |
| [OpenGaussian](https://arxiv.org/abs/2406.02058) | 针对弱特征表达、错误 2D–3D 关联，先学一致实例特征和两阶段码本，再建立实例级语义关联 | 结构身份和语言语义分工，比直接混合所有特征更切题；实例粒度仍不涵盖全部部件查询 |
| [OpenMask3D](https://openmask3d.github.io/) | 无类别 3D 实例 proposal 与多视角 CLIP 特征结合 | 分开验收 proposal 覆盖与语义选取；依赖 proposal/几何质量，不能直接视为 LERF 协议基线 |
| [MaskClustering](https://arxiv.org/abs/2401.07745) | 全局 mask 图，利用其他视角对两个 mask 的共同支持进行一致性聚类 | 用多视角共同证据建立身份，不能依赖同词或单次邻帧 IoU；也要防整体与部件误合并 |
| [GARField](https://arxiv.org/abs/2401.09419) | 物理尺度条件亲和场，明确建模粗到细层次 | 不同范围可能都是正确监督；必须按尺度解释，不能全部当冲突标签 |
| [SAGA](https://arxiv.org/abs/2312.00860) | Gaussian 尺度门控亲和特征，SAM mask 对比学习，2D visual prompt | 适合补齐交互范围能力；不是单靠增加 gate 就完成文本 grounding 或任意 2D prompt 协议 |
| [OpenScene](https://arxiv.org/abs/2211.15654) | 融合多视角 2D 特征并蒸馏到与文本/图像对齐的 3D 表示 | 保留原生可查询空间是有效主线；不必要求所有能力共用未经约束的投影 |
| [2D Gaussian Splatting](https://arxiv.org/abs/2403.17888) | 面元表达、深度畸变和法线一致性约束几何 | 几何需验收表面与多视角一致性；不能把“改用 2DGS”本身视为解决 MoGe 尺度和对应的证据 |

可迁移的共同原则是：先获得可靠空间对应；以粒度一致的结构表示对象范围；将原生语义绑定到这些范围或稠密元素；查询时分别处理身份与范围。无需把八个方法全部接进系统。

## 8. 收敛后的实施与验收顺序

1. **几何/对应验收**：完整贡献分布对照可靠源轨迹，分视角、遮挡、边界报告中位/p90/坏点率与覆盖；联合尺度方案必须在留出点通过，不能只看拟合误差。通过后才冻结、重建绑定资产。
2. **范围证据重建**：验证视角间身份和粒度，建立可重叠层次，分别报告候选 coverage、正确身份关联、原生选择与 oracle 差距。先有可信监督，再学习结构场。
3. **统一范围读取**：保留原生 query 语义，替换硬范围接管；让文本/图像使用共同的结构能力，交互提示明确身份和尺度。逐级检验 native score、最终 score、渲染 membership，而不是只看教师 MSE。
4. **跨协议验收**：明确 LERF 类别 union、ScanNet OVS 的点级标签映射与 ignore、NVOS 的授权 reference scribble 与目标范围，各自冻结输出合约，再做共同方法身份的对照。先开发集，再独立留场景评估。

暂不优先：增加教师、增加 latent 维度、加训练时长、调整单个阈值、扩大不受约束 union。已有失败控制说明这些做法没有解决根因。也不将“一个 96D 场”当作不可验证的科学前提：可以增加显式标注为放宽约束的结构/原生空间对照，测量表达上限；若生产方案改变已记录架构约束，应更新 ADR，而不是隐藏第二套地图。

当前证据支持纠正上述三个系统环节，不支持宣称已经实现大幅性能突破，也不支持无条件回退历史全部架构。
