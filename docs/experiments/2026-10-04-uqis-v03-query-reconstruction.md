# UQIS v0.3：修正查询构造，形成可运行的四模态开发候选

日期：2026-10-04。主线方法仍为system_v6，本轮未训练／运行新模型，未产生新的模型精度。

## 结论与适用范围

UQIS适合检验“固定同一地图，使用text、image、2D正点、3D正点召回同一三维目标”。
本轮将旧候选中的确定性构造问题修复，并交付9场景、67个官方实例、268条查询的v0.3开发候选。
旧v0.1/v0.2数据、查询和成绩均保留。它尚不是完成独立认证的正式最终测试集。

这套基础轨道覆盖官方实例召回，不能据此宣称部件、同类全部实例、多轮正负交互均已验证。
成组书本、毛巾、柜子等官方实例仍保留其原范围；“一个标注实例”不保证是单个物理物体。

最终数据：`output/scannet_uqis_9_v0_3_candidate/release_final`。
维护入口：[使用说明](../benchmarks/uqis.md)，`radio_gs.benchmarks.uqis`。
同目录此前的`construction`、`registered`、`release`是中间候选，不是交付版本。

## 已解决的实际问题

1. **提示点与目标脱离。** 由原始RGB-D像素反投影，要求最近官方mesh顶点属于目标且距离不超过5cm。
   2D与3D提示使用同一观测，2D明确提供原生深度相机栅格及内参，但不提供深度或RGB。
2. **边缘吸附与RGB／深度视野错配。** 距离变换显式填充图外背景，点须位于可靠目标内部，
   并同时满足深度栅格与RGB视野边界条件。RGB裁剪使用两相机实际内参配准，保持方形纵横比例。
3. **清晰参考与建图信息互相挤占。** 不再限制每景最多3个查询帧。按统一清晰度、曝光、面积、
   目标占比规则选参考，再联合检查排除这些参考后是否仍有足够建图观测。
   初版scene0535的窗口只剩4个采样建图帧可见；联合规则将窗口参考从440帧改到400帧，
   与另一目标共用参考相机，恢复5个可见采样帧，无需删除目标或放宽旧标准。
4. **虚假的“无关系Core”。** 保留67条原始表达，为全部文本逐条增加可重叠的语言能力标签。
   含空间表达50条、比较22条、属性19条；不将这些标签冒充人工独立身份或唯一性认证。
5. **任务边界和评分输出不清。** 拆分method、mapping、evaluator内容；查询进程仅获得一次
   query和公开mesh坐标，目标身份、配对、实例标签及源帧路径留在构造／评价端。
   新版本生成新ID；四模态分别统计并保留逐query指标。单模态对照不伪造四模态汇总。
   同类干扰范围补全为官方标注中实际存在的同raw-class实例，不限于入选67目标。

构造只读取合法源数据及构造标注，不读取方法预测来挑查询。没有用评价分数删除难例，
没有对照片做生成式修补。每20帧扫描候选是明确的构造预算，所有合法建图帧仍完整列出，
不存在沿用旧120图实验预算作为benchmark上限的问题。

## 保持的严格输入合约

- 查询阶段只读地图与合法query。image的参考裁剪属于query本身；不开放源照片库。
- 2D点只给相机、栅格和正像素，不增加RGB、深度或SAM结果。
- 本次为官方mesh／RGB-D辅助几何轨道。官方mesh由完整扫描生成，不能声称其几何也
  排除了参考帧；新的视图排除约束特征建图观测。RGB+MoGe轨道需要另行固定并分别报告。
- 新参考帧导致旧地图中**62张已使用照片**落入当前禁止集合，涉及全部9景。
  旧地图／预测不能直接沿用为v0.3严格成绩；后续必须按照新版合法帧重建。
- 该67目标及9场景已经在历史开发中打开。不能将它们重新命名为未见最终测试集。

## 剩余缺口与下一步顺序

**参考信息仍有缺口。** 18项困难包括模糊、过曝、镜面反射、背景占比、局部可见和身份／
标注歧义。逐条记录在`reference_visual_review.json`，并通过图片哈希绑定到最终包的
`evaluator/reference_review.json`。助手审阅不是独立人工真值，也没有据此缩小主评价集合。
某些空间指代表达缺少查询视角上下文时是否唯一可解，仍需结合完整场景独立核验。

**集合读出仍需独立校准。** 当前四模态主报告为逐场景宏平均AP，附场景bootstrap区间。
固定0.5 IoU、purity、coverage及oracle IoU保留诊断地位；不能把排序成绩当作完整对象
已经取出的证据。下一步先用其他场景固定阈值／实际集合输出，再报告正式IoU。

**尚未完成同地图四模态方法比较。** 后续顺序：处理参考身份／信息不足 → 建立独立校准
及最终场景 → 按新版排除集合建图 → 完成RADIO-GS四模态mesh输出与明确输入权限的对照。
当前v6的源辅助路径不能原样用于本轨道。地图数量、冻结时点、各模态依赖和存储／查询成本
应随真实运行记录；四个独立分支拼出的成绩不能证明统一场。

基础实例轨道稳定后再增加有真实标注支持的部件、同类集合和多轮交互。此次交付解决了
构造与评价入口的具体问题，没有宣称benchmark全部完成，也没有宣称模型精度提高。
