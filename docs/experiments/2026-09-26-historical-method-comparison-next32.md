# 历史高分与当前主线：实现、权限及可移植部分

本报告只核对本地实现、原始结果和冻结协议，没有重新训练或运行目标评估。机器记录位于 `output/historical_method_comparison_next32/final_audit.json`；其中分别记录当前文件哈希和历史绑定是否匹配，不改写旧结果。

## 先明确结论

**不能把目前的问题概括为“新方法所有指标都不如历史”，也不能用历史最高58.89%作为无条件恢复目标。** 目前最清晰的历史差距是选中元素的完整范围；同时存在此前汇报容易遗漏的LERF2D读出差异。历史的确有值得移植的方法，但必须移植计算关系，而不是旧分数和旧参数。

## 一个必须补齐的比较缺口：当前LERF2D不是旧官方读出

冻结外部协议 `evaluation_protocol_freeze_20260801.yaml:42` 要求Occam/LangSplat读出：30×30 OpenCV滤波，与原响应均匀混合；每尺度min–max及线性变换；固定阈值；7×7掩码处理；由响应而非GT选择尺度。定位使用平滑峰值。旧51.7373%结果绑定这一完整配置，4场22相机208观察，结果原文件及renderer receipt仍存在。

当前 `evaluate_full_field_rebuild_next19.py:114` 则渲染校准后的单元素概率，除以被观察元素贡献，在同一原图GT栅格以`.5`二值化，定位直接读取**未平滑**概率最大点。没有30/7算子、逐尺度min–max或独立多尺度图。代码是确定的，next31也精确复现父结果；问题是**它不能仅凭“相同标签和IoU函数”被称为与旧51.74、Occam63.62或LangSplatV2同协议**。旧58.89的定位还用了另一种polygon argmax，三者更不能混用。

正确处理是保留所有旧封存，再添加明确命名的统一外部协议结果。固定地图和查询编码，在合法输入下导出连续分数，调用既有 `eval_ours_lerf2d_scalar_maps.py` / `eval_prerendered_lerf_features.py:238`；绑定原始分数语义和渲染算子。新的分数不能覆盖当前49.74的身份。已有二值PNG不足以恢复连续响应、尺度选择和AP，不能拿PNG模拟这一步。

当前“LERF3D”评估仍是选中3D元素的2D投影轮廓，不是独立物理3D真值。旧42.93经同一个公共PNG scorer恢复是真实证据，但旧路线还使用`.6`元素阈值和`peak_component_retention_guard`；当前`.5`选择后直接渲染。因此先在**相同几何、相同阈值选择定义、相同最终投影**上比较，才能分责给范围模块。

## 历史实现真正做了什么

### 早期显式–hash并不等于现在的元素场

`HybridFeatureGaussian.decode_screen_space`（`hybrid_gaussian.py:807`）把已渲染的局部latent送入fine decoder；用渲染深度反投影的位置查询hash，送入coarse decoder；最后非线性融合。训练入口 `train_feature_field.py:2565` 正是这个顺序。点查询却在单点latent/坐标上执行同一网络（`:880`）。

“先平均再过非线性网络”和“各点过网络再平均”不同。已有固定合成审计最大差0.0257484，足以否定算子恒等性，但不是实际数据误差估计。因此早期好看的2D边界不能证明其单元素语义和直接选择同样好。早期配置是30k RGB-3DGS几何、240epoch特征训练和16层hash，而不是当前MoGe冻结几何及96D原生/结构分区；完整目标相机几何训练排除链也未由这些配置证明。

后来 `CanonicalGaussianField.coefficients`（`canonical_gaussian_field.py:124`）已经给出了兼容做法：**在每个元素上先完成local/hash/reliability融合，再用共享仿射basis解码**。`AffineBasisDecoder`（`basis_decoder.py:157`）没有归一化和非线性，故与归一化线性渲染交换；后续cosine、softmax和概率校准仍然不交换，必须按实际部署顺序监督。历史promoted紧凑核心是local128→coefficient256→RADIO1280，且保留的示例明确是`nohash`；不能声称历史高分已经证明hash必需。

### canonical路径：先重建稠密能力，再按物理范围形成语义

历史canonical-mpr-v3用几何和实际渲染贡献注册RADIO稠密观察，训练可直接读取的元素特征，以原生DINO/SAM能力及实际渲染共同约束。文本不是将RADIO空间token直接冒充全局SigLIP语义：全局训练的SurfaceRegion summary head聚合3D区域，再经过官方SigLIP summary head。

`SurfaceRegionSummaryReadoutV2`（`surface_region_summary.py:511`）显式使用anchor、相对位置/尺度和core/context；`:640`的独立core/context变体避免增加背景token改变core的平均值。旧51.74结果保留0.25/0.45/0.70米三种范围直到读出，其选择依据是响应峰，不是逐query最佳IoU。它保持不同语义粒度的做法值得参考，但现有旧权重输入是RADIO1280，不能直接套在当前SigLIP64+结构32场上；它也不是所有VFM都已等价蒸馏的证据。

### identity–extent：语义身份与对象范围各有证据

8月17日方法先算场的原生身份响应，再利用32个合法源视角的query-free SAM多尺度proposal、1536D原生SigLIP裁剪描述符和几何传递来确定范围。`build_lerf_sam_siglip_object_posterior_scores.py:208`计算原始身份，`:216`另算kNN/min–max范围基线，`:240`构建范围；`:283`把`identity_query_scores`独立保存用于定位。历史四场范围IoU从31.4175%到39.5842%（观测加权），定位逐项保持87.9808%；这是这套历史方法内部有效的受控收益，不能移作当前字段的成绩。

8月20日控制将proposal和“保持原生场”的null分支一起归一化（`latent_proposal_posterior.py:63`）；未知或无有效proposal时逐位回退。这个概率结构可移植，但其**证据构造不能原样照搬**：`sam_siglip_object_posterior.py:152`按每proposal最大值归一化membership，`:240`用最大Jaccard/包含重叠作对应强度，`:275`相对本query最佳proposal设门槛，并用手设组合权重。包含关系不是同范围身份证明，多视角相关性也未充分分离；纯null混合会稀释每个proposal，不能自动表示多个同类实例。它没有逐query读取目标IoU选赢家，但仍不是已校准、物理正确的对象概率模型。

query-dependent score cache只是上述读出的缓存，query-free membership/crop teacher等依赖仍属于实际执行资产。9月14日确实从哈希绑定的这些资产重建了所有query scores，而非只抄旧分数；这仍不是仅凭一个96D场就能冷启动的同容量方法。

## 不能移植的“高分捷径”

- 58.8944%路线：同4场温度50/40/25/25、阈值扫描、后验守卫；SAM源伪掩码由评估标签目录里的精确词表触发。虽不在推理时读取目标RGB，也不满足当前开放query源写入合约。旧SAM边界头自身只带来1.8222点；迁到另一冻结场仅带来0.9786点，解释不了全部分差。
- 旧direct3D50.14%：同目标队列选择`.55`阈值，0.5%保底、3%/5%数量上限，且对目标RGB执行GrabCut。不是原selected集合投影的同一输出。
- 旧ScanNet38.06/38.71/47.11%：标注网格行查询、场景中心化和mesh-kNN参数在同8场选择；不应混入37.8633/41.9794/52.3408%的canonical Gaussian-domain记录。
- 旧NVOS74.7771%：有明确负scribble override，不能当作positive-only对照；LUDVIG91.2577%具有all-view target RGB和在线SAM权限，不能将差距全算给蒸馏。当前81.1608%也只是开发控制，不能倒推已公平超过旧方法。
- 旧typed identity定位与extent IoU分别取不同语义输出。可以作为预先声明的方法设计，但不能在新候选定位下降后换用父定位分数、仍声称同一个新概率图全面改善。

## 最值得实现的一项方法迁移

优先迁移**“按来源和范围保留证据，再进行原生查询比较”**，而不是再迁移一次无约束图传播或将旧hash接在渲染后。

1. 复用当前几何、教师和合法源预算，保留原生语义前缀。把区域证据按可信同范围关联分组；整体/部件包含单独保留，无法验证的对应不合并。`SurfaceRegionV2`的anchor/core/context以及物理尺度是可复用输入组织，不强制保留其RADIO依赖。
2. 在**实际元素评分→真实渲染**之后监督本query与易混淆query的相对差值、范围IoU和实际选择；只对可靠互斥范围建立负例，整体/部件不强制互斥。已有源侧二值IoU提升但ScanNet类别召回下降，说明这一约束具有直接动机。
3. 加有限、可拒绝的范围残差，保留原生高置信判断；不能直接用单峰或descriptor相近便令整个parent替换局部身份。null/回退结构可借用旧实现，关联证据和准入必须重做。
4. 同容量、同预算比较基础场、无分组新监督、保留范围的新监督，先在未参与分组决策的源视角评估文本/图像排序及边界；通过后完整运行四个冻结队列。不按场景、类别或目标IoU拼接赢家。

这是一个可验证的高影响方向，不是已获得增益的声明。next31两槽mixture已经失败，不能把“增加几个向量并softmax/max”包装成新的充分解决方案。若这一步仍不能保留查询排序，再研究primitive-local可烘焙hash残差；不得让辅助结构教师重新改写受保护的原生语义坐标。
