# NVOS N07：原参考查询的跨视角记忆传递

ADR0030 在本轮预测前登记；分支 `codex/tmm-query-response`。正式运行
`nvos_memory_response_v1`，全八任务七分支的 56 张预测封存后才打开 GT。

## 实现与完整结果

原参考正向 scribble 所生成的保留 SAM 掩码，通过相同冻结 SAM3 权重的
记忆模块传到目标 RGB。分别用参考／目标两帧，以及两者之间合法源视角的
规范序列；再在原 v10 已观测高斯域写回。静态密集响应分支复跑 N04。
没有新负点击、人工框、目标 GT、逐任务分支选择或几何改动。

SAM3 的记忆模型是已有外部教师能力，不能作为本文新发明。本文检验的是
原查询身份能否绕过旧三维响应压缩，形成更可靠的响应修正证据。

## 判断与归因

序列记忆超过 v10，但未超过 N04；不升级为主线默认。两帧与序列的整体
均值相近，增加中间视角没有形成稳定增益。fern、flower 与 horns 的局部
改善不能与其他分支的局部赢家拼接成一条结果。

orchids 的参考种子可见下方花朵只有碎片状支持，记忆传递仍未完整恢复。
这说明“正确传递已有身份”与“恢复完整对象范围”是不同能力；只加记忆
并不能保证完整查询粒度。该源端观察不是参考 GT 准确率，也不能代替
对范围完成机制的后续受控验证。trex 的细结构与排除背景问题仍未解决。

本轮不继续搜索序列长度或提示常数。N08 已在 N07 出分前固定，使用相同
三类图像证据，独立检验半分辨率写回与最终读出射线不一致所造成的损失。

源教师 Huber 残差仍逐任务保留；教师不是真值，不能把一致性直接当真实
多视角精度。N07 为视角条件开发结果，未测 AP，尚未达到 SOTA。

## 正确性与复现

- 静态图像分支八任务连续数组哈希全部与 N04 一致，两个 GT 口径 IoU 精确复现。
- orchids 的两帧与序列路径相同，两者连续输出哈希一致。
- v10 重渲染、独立稀疏投影、透明度累积、原支持域保持均通过运行时检查。
- 两种 GT 口径逐任务独立整数混淆矩阵、任务均值与完整封存均核验通过。
- 源码／配方／输入／权重哈希和原路径列表保留，不保存中间视频、稠密特征或新权重。
- 其他四个 benchmark 为哈希绑定的既有结果，不冒充新推理。

入口 `scripts/research/run_tmm_nvos_memory_response.py`，配置
`configs/research/nvos_memory_response.json`。重跑必须用 `--run` 指定新目录。
空间诊断 `nvos_memory_spatial_v1/errors.png`；表格与逐任务 CSV 已由统一
反馈生成器输出到 `paper/tmm_response/`。

N08 在失败后需要重新生成临时图像响应，故完整复跑为
`nvos_memory_response_v2`。全部24张直接教师响应和8张 v10 响应逐字节一致；
其余24张三维写回存在浮点差异。仅 trex/序列写回在评分网格少1个 FP、
多1个 TN，两种 GT 口径均如此，平均 IoU 变化 +0.0000053 个百分点。
因此不能称为全部预测逐位相同；N08 使用 v2 的精确父响应作为对照。
v1 仍为 N07 正式登记结果，两个版本及差异记录均保留。

## 外部 SOTA 协议补查

[VCAR 官方 NVOS 说明](https://raw.githubusercontent.com/DDKK0526/VCAR/master/configs/nvos/README.md)
明确默认只有七个目标、不含 horns_left；其发布的点、框和参考帧来自自身
历史配置，并非本项目直接沿用的原始 scribble 契约。该差异现已有源码证据，
不再仅是猜测。不能依据 VCAR 对 LUDVIG 的叙述反推本地 LUDVIG 八任务设置。

[评估实现](https://raw.githubusercontent.com/DDKK0526/VCAR/master/eval_utils/run_nvos.py)
使用 GT>128，选中高斯的 alpha>0.1，并先二值化后最近邻调整尺寸；
本项目为连续语义响应先双线性调整尺寸再按0.5评分。提示、几何、读出与
队列都必须分别披露。其 README 写第二轮阈值0.8，但实际 CSV 全为0.9，
复现时须核对发布配置，不能凭论文均值默认全部一致。

官方快照固定到提交 `87fc06b0d7e08f125955e7e4271e875273082b8e`，
仅约31KiB源码／元数据，记录于 `nvos_vcar_protocol_release_v1`。
没有下载模型或更改本项目八任务口径。公开93.5仍是追赶目标，不是已完成
同条件认证的排行榜门槛。
