# next40：直接范围监督与参考身份选择

## 结论

本轮完成方法实现和完整开发对照，**有局部有效改进，没有解决全面泛化，也没有达到四项共同显著提升**。保留 next38，新增方案作为显式可选研究路径，不按场景拼接最好成绩。

核心问题仍是：**源区域描述、查询所指身份、三维元素范围不是同一个监督量**。把原生语义空间保留下来，或者把已有分数在图上传播，都不能自动补齐这三者的对应。本轮直接训练查询范围，并让参考提示直接选择已有跨视角范围，检验了两条更直接的解决路线。

## 一、从“拟合旧分数”改为直接重建源查询范围

实现 `source_kernel_extent.py` 和 `fit_source_kernel_extent.py`：

1. 从已有源 caption/SAM 证据提取原生文本锚点。同一源视角内同一文本的多个检出构成类别范围并集；不同文本不合并。没有检出不是负例。
2. 正例来自高置信源掩码；负例只来自原生区域亲和显著低于该查询正区域的其他高置信掩码。它仍是启发式伪负例，并非真实身份标签。
3. 通过固定源渲染贡献联合求解元素范围残差，保留原语义场作先验。原生文本核连续组合残差，避免把查询硬分配给唯一训练概念。没有修改编码器坐标、几何或图像分支。
4. 60 步、先验 0.1、文本核浓度 20；ridge 在 0.1/1/10 中仅按保留源视角范围 IoU 选择。每五个源训练视角保留一个用于本次范围拟合验证；原场已看过这些源视角，不能称为独立地图验证。
5. ScanNet 保留原先获源证据支持的类别范围读出和分类校正，新增范围作用于同一基线。额外分类实验用源词汇的每一个已确认正概念对已确认负概念排序，未知排除，不导入评估类别词表。

结果说明：直接空间监督能改善一部分类别，但当前伪掩码/伪负例与开放词汇整体、部件语义仍不完全相容。**原生坐标未变不等于原生判断未变**；新增范围证据仍会改变输出，这是必须实测的能力取舍。LERF 源范围改进并未转成实际选择提升。

### 本轮原型中的读出错误已修正

早期原型使用 `logit(clamp(sigmoid(base_logits)+delta))`。即使 delta=0，概率截断也会抹平极低分之间的类别排序。在已有 next38 分数上只做这个往返变换，scene0000 有 1191 行类别改变，scene0070 有 2617–2620 行改变（全地图行计数，未限定可评估支持域）。

这是**本轮新原型的错误，不是已证明的旧主线错误**。改为：

`base_logits + logit(clamp(base_probability+delta)) - logit(clamp(base_probability))`

零修正保留原 logits；饱和区保留原相对证据。源验证选择也改为实际部署的修正读出，完整重跑 LERF4、ScanNet8、分类8 和图像4。上表只使用重跑结果。它是对数几率增量，饱和区不等价于直接替换概率。

新拟合/运行脚本默认 `--readout odds`；旧 payload 未标记时继续按旧读出复现历史结果。此前 probability 原型的 ScanNet 表现不作为有效改进证据。

## 二、先用参考提示确认身份，再选择三维范围

`reference_scope_completion.py` 将已经构建的跨视角范围投影到授权参考视角，用提示连通的参考 SAM 区域选择范围组合，要求组合保持参考精度且 IoU 至少 0.5，然后为相应三维成员增加正证据。参考未覆盖部分保持未知，不作为负例，也不删除原结果。

与旧的“用范围解释当前场分数”不同，此处有独立的参考图空间依据。它不需要目标图，也不是给 SAM 增加语义分类能力。这个改变得到完整 NVOS8 的 AP 增益，但参考兼容仍不能保证不可见区域身份正确；一侧补全也不能删除原有假阳性。

## 三、已完成但不采用的路线

- **全局图割**：三种完整 NVOS8 对照均不优于父实现。扩大邻接的版本尤其伤害 leaves；恢复旧邻接大幅减轻退化，但仍没有整体增益。结构不能自行判断“哪些相似部分属于本次目标”。停止继续扫图强度。
- **共享范围基的文本残差**：figurines/ramen 两场景没有有意义增益，保留源视角都选择强 ridge。把自由元素替换成范围系数，不能补齐身份监督。
- **跨视角一致性弃权**：两场景仅约 8–10% 的有观察元素—查询对满足当前双视角纯正/纯负条件，接近父结果。比例受观察质量、检测覆盖和质量阈值影响，不是几何错误率；只减少冲突不等于学会补全。
- **实际选择渲染联合优化**：两场景使用硬前向选择、软不透明度梯度，同时监督概率和实际选择，未取得有意义增益；源负监督排除缺乏可见依据的隐藏几何。这些早期范围控制沿用旧 probability 原型，未作为修正后模型的能力结论或升主线依据。
- **仅原生底座范围重建**：两场景未超过现有组合底座，不替换保留能力。

这些控制限定了本次实现，不证明相关方法思想普遍无效。没有新增单元测试、防御性编程框架或审计系统；运行的是方法训练及真实开发评估。
