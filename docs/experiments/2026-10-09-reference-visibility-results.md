# 可见参考匹配与实际对象选集：完整八例对照

本轮接续[参考输入/组合研究](2026-10-09-reference-scope-results.md)，完成一个独立
方法干预。冻结99b2a18；八请求、七冻结场、旧120来源、同一批保留的SAM参考查询
mask。不是原始scribble输入；继承参考RGB/SAM生成成本，本轮未重新生成mask。
无新增训练、场状态、源RGB/跨视图mask/tracks或旧拟合器。

## 方法改动

旧组合用候选Gaussian子集单独渲染的alpha匹配当前参考mask，会移除其他场景物体。
新候选保持完整场景透射关系，投影区域成员分数，并在观察到的Gaussian质量上
归一化（观察质量比例>0.5，否则弃权）。区域集合B+>0、成员可用域、mask输入、
0.5候选阈值、贪心soft-IoU标准和最终二值Gaussian集合都相同。

这是参考观测算子的改变，不是改变目标端评分。目标实际选集仍独立重算透射率；
保留响应仍用原整场归一化。可见参考相符不保证完整隐藏部分属于同一实例。
新模式通过Runtime.reference_scope(observation="scene")显式调用；默认不变。

## 联合归因与当前架构责任

两轮共48份条件预测覆盖同八请求，不是48个独立样本。
第一轮中，相同扩展mask下，组合实际64.1988→84.8863，七例升/一例降，说明
不能把扩展输入仅转成更多局部射线；明确的对象范围组合确实改变了有效功能。
第二轮表明，参考遮挡处理和最终实际选集是两个责任，修正前者不保证后者同时变好。

全部八例错误图已检查。orchids仍漏掉底部花簇，trex及fern仍有边界/孔隙误选。
这些图只说明错误形态，不能单凭视觉将全部错误归因于某一项。
参考fit也分开保留：例如fortress可见匹配soft-IoU97.65%，同集合在参考视图单独
渲染的fit87.73%，不能把二者等同。不同候选在参考视图可能具有相同可见形状，
却带来不同隐藏范围；当前形状匹配没有独立判断这种范围是否属于同一对象。

下一功能责任是：可见输入的可信对应、不可见新增部分的身份判定、实际Gaussian
边界与分级成员置信度。当前二值组合会损失排名信息，不能拿它直接替代UQIS的
分级读出。v10的跨视图实例对应仍须在场内实现并验证；不能将SAM部分坐标的保存、
更多监督或训练收敛当作该功能已经恢复。三教师职责、单场状态和标准推理无源访问
保持；参考RGB/SAM生成、额外监督、来源扩展必须继续分别列出。
