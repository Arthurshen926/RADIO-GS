# ScanNet：显式旧方法对照与统一原生场重建

十个场景、1158 张合法源图的统一原生地图已经全部重建并重新评价。旧八场景也从地图权重重新生成预测、复现保留结果。新地图使用与 LERF 共用的写入数值核，但同几何匹配八景的 19 类 mIoU 为 **46.9743%**，低于旧地图 **50.1230%** 和旧源辅助 **53.9376%**。因此本轮完成的是可重建基线与明确分责，**没有把较弱的新图提升为性能主线，也没有达到 SOTA 的证据**。

## 已完成的旧八场景重算

`configs/consolidated/scannet/cohort.json` 显式声明地图、查询和评价输入。`run_scannet_query.py` 重新编码文本，从地图权重重新计算原生字典、范围和类别校准，再使用已声明源图教师掩码重新求解。没有把历史 `scores.pt`、`elements.pt` 或预测标签作为运行输入。

| 八场景平均 mIoU | 19 类 | 15 类 | 10 类 |
|---|---:|---:|---:|
| 地图读取，逐点评价 | 50.1230% | 51.3217% | 64.4320% |
| 源证据辅助，逐点评价 | 53.9376% | 54.5026% | 67.6800% |
| 源证据辅助，旧体积加权 Gaussian 伪标签评价 | 59.2471% | 59.4852% | 73.2194% |

源证据辅助结果复现保留结果。本轮新计算不等于新方法提升。两种评价域差约五到六个百分点，不能将后者与公开点云成绩直接比较。旧配方包含 96 维多教师场、64 维原生解码分支、512×1536 原生字典、范围组合、源侧阈值校准和类别竞争项；它是 `legacy_category_memory`，并非最新 LERF 原生场的同构重建。

完整输出：`output/scannet_runtime_integration/summary.json`。冻结的合法源检测缓存属于可重用教师输出；本轮没有声称重新运行这些教师。

## 统一的十场景新地图

所有场景使用同一条流程：

1. 从 `transforms_train.json` 读取所有 1158 张合法源图及相机；以不含语义标签的 `points3d.ply` 构建冻结表面 Gaussian。
2. 对源图生成同一 SAM3 三层、21 个窗口、768 个点提示的查询无关候选。旧缓存只有在源 RGB hash 与完整生成配方一致时复用。没有源图数量上限。
3. 每个非空候选以掩码外灰色、边界框外扩 3 像素的原生 SigLIP 图像编码生成 1536 维描述。取消编码阶段旧的 .002–.6 面积筛选；生成器自身的公开配置仍明确保留。
4. 调用与 LERF 共用的 `radio_gs.pipeline.native_reconstruction.NativeFieldAccumulator`。序列化 fp16 描述先归一化，重叠区域构成像素语义方向，冻结 alpha 贡献将其累计到元素，再归一化存储。
5. 查询直接使用同一 SigLIP 原生文本坐标，与元素向量作余弦比较。类别任务分别在 19/15/10 类中取最大响应，未观察元素输出 void，不从评价分母剔除。

新地图不以旧类别预测或旧场输出作目标，也不使用语义标签、查询相关校准参数或测试集阈值。原生写入核统一并不意味着重叠的整体/部件已经被正确分解。它是可完整重建的共同基线，不能自动视为机制创新或性能进步。

新入口：`scripts/research/run_scannet_native_cohort.py`。单图建图：`scripts/research/build_scannet_native_map.py`；单查询运行和两种评价域适配器：`run_scannet_query.py`、`evaluate_scannet_runtime.py`。配方：`configs/recipes/scannet_unified_native.json`。新增类别地图 provider 为 `native_category_map`，当前仅提供 map-only 类别响应，没有独立集合解码头或新在线源查询 provider。

## 源辅助能力尚未完整迁移，不能用 map-only 取代它

现有可确认的类别源证据是 `output/typed_evidence_next44/scannet_<scene>/identity_<frame>.pt` 和对应检测，共旧八景 **176 张合法源图、19 个规范类别**。这些是源图教师输出，允许复用，但仅覆盖本轮 1158 源图的一部分。`scene0200_00` 与 `scene0645_00` 没有对应的类别 SAM 缓存；早期 RADIO→SigLIP 特征缓存和旧训练预测不能代替独立范围证据。

本轮新生成的是查询无关区域，不是已经确认的 19 类正负范围。因此没有将“query-free 区域存在”改称“类别监督已补齐”，也没有只给八景接强源头、再与两景纯地图结果拼成十景方法。

若仅补两景，至少需 272×19＝5168 次文本检测；若源辅助也使用完整的 1158 源图，复用已有 176 帧后仍需 982×19＝18658 次新文本检测。后续还需统一原生余弦与源响应的刻度、保留类别竞争语义；直接把 LERF 二值概率头接到未标定的类别余弦上不构成合理整合。

旧八景与新地图对应八景的 geometry SHA256 全部相同，逐点转移也相同，因而性能差不能归因于更换几何。新原生 map-only 与旧 source-assisted 的差异仍同时混入了**范围/校准模块移除、语义写入和监督配方变化、源图数量变化**，不能将差值直接归因于某一个机制。已保留的旧八景 map-only/source-assisted 配对能衡量旧源头贡献，而新十景结果首先是共同建图基线。下一完整源头迁移必须在同一新地图、同一源输入条件上比较。

## 评价边界

主要报告原始标签网格顶点上的等权逐点评价，以最近 Gaussian 中心转移预测，不设按标签选择的距离阈值。各场景对存在的真值类别求均值，再对场景求均值。语义预测先生成并保存，标签只进入评价。

这补齐了十场景数据与可重建结果，但仍不宣称已与某个外部方法的全部公开协议和输入公平性等价。当前轨道显式获得无标签网格几何，需逐一核对对比方法是否获得相同网格或深度，以及是否另行优化几何。[LUDVIG 官方复现说明](https://github.com/naver/ludvig#reproducing-results)要求已训练的 Gaussian 场景。不能以同样场景名称消除这个差异。

本轮没有 UQIS 实验、独立未调参场景、紧凑化验收或同一新 ScanNet 地图四 query 的准确率评价。旧八场景与新十场景分别报告，不做逐场景赢家拼接。

## 实际完成量与成本

- 三层 SAM 覆盖 **1158 / 1158** 源图；同配方缓存复用 272 帧，新生成 886 帧。全部非空候选产生 **73905** 个原生区域描述。
- 十图共有 **1,569,975** 个元素，**1,547,921** 个有特征贡献（98.595%）。未观察元素在评价中保留为 void。
- 原生场文件合计 **4.825 GB**（4.493 GiB）。此数只包含 native_field.pt，未包含几何、源图、教师模型和缓存，不能作为完整部署成本。
- 调度记录的 GPU 工作者占用时间合计 **4.555 小时**，主队列墙钟 **68.24 分钟**。这是分配 GPU 的工作者墙钟之和，不是硬件忙碌时长；不含历史缓存/模型创建与最初中断任务已完成的 17 帧 SAM 成本。
- 0062、0097、0200 在共享数值核切换前开始建图，已全部复用区域描述重新写场并重算查询/评价。最终十图均使用同一 `NativeFieldAccumulator`；没有混用两种写入实现。

结果、逐类诊断和成本：`output/scannet_native_completion/summary.json`；完整显式场景/查询/评价队列：`configs/consolidated/scannet_native/cohort.json`。运行记录已经收尾，ScanNet 没有遗留 GPU 任务。

## 对系统收敛的结论

保留旧八景有效源头，完整新十景作为共同原生建图基线。下一项方法工作应在同一新地图上迁移类别范围证据与类别竞争/刻度机制，再以同输入对照验证；不能把“补齐源图和共享 writer”直接解释为完成统一语义系统。当前依然没有新十景的完整源辅助头、同一 ScanNet 地图四 query 准确率证据、紧凑部署证据或独立新场景泛化结果。UQIS 继续暂停。
