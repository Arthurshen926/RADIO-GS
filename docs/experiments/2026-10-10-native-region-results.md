# 原生区域查询函数：完整 LERF 验证与下一步收敛决策

本轮完成四场、68 文本查询、五组对照。全部预测封存后再评测；代码冻结
`2bb4bb8cc160e8da0897a6b7b4cd61d0cd827df5`。运行目录
`output/query_field_20261010/native_region_functions_v2`。没有恢复实际选集性能，主方案不提升默认。

## 实际改动与固定条件

把既有 72 源帧、5137 个部分区域的原生 SigLIP 描述子按原始区域索引绑定进同一
field.pt；核对旧 B 正负/关联坐标、视图、尺度、源哈希和训练/开发分离。
不增加源帧、训练或监督；不存历史查询答案，不在查询时打开源 RGB/mask/track。
新增场张量 15,780,864 bytes，四场总张量 30,591,186,984 bytes，仍是未压缩能力参考，
不是紧凑系统或效率贡献。语义测度原本的更大来源预算未改变；新增绑定只覆盖既有72部分证据视图。

查询先在区域上计算 sigmoid(10*(query cosine-max generic-negative cosine))，再进入
相同 Gaussian 正负证据更新；阈值保持0.5。空间平均/原生接受各自的保护与不保护
路径共享同一份 P/N，消除上轮对照中重复稀疏聚合造成的混杂。公开 Runtime.text_union
提供 native_parts/native_protected_parts 可选路径，默认不变。原始查询编码未重跑，
使用绑定的当前查询向量和先验 fixture；冷启动额外验证一个公共接口查询重建先验。

v1 在仅 figurines 预测完成、任何目标评分之前停止：发现 FP16 存储精度被继承到
查询运算。v2 明确使用 FP32 计算，匹配既有原生语义函数。v1 的设计、预测和
aborted_before_scoring.json 保留，没有看目标分数后调参或覆盖旧结果。

## 完整结果

| 条件 | 响应 IoU % | 实际选集投影 IoU % | AP % | 选集 Precision % | 选集 Recall % |
|---|---:|---:|---:|---:|---:|
| admission | 55.3608 | 42.9498 | 82.8793 | 46.2069 | 84.1598 |
| pooled_parts | 57.2624 | 42.3954 | 81.3072 | 45.6199 | 84.2134 |
| pooled_protected | 58.3877 | 42.2742 | 82.1015 | 45.4751 | 84.2635 |
| native_parts | 61.5980 | 41.5689 | 82.6430 | 43.1702 | 87.0391 |
| native_protected | 61.3865 | 40.8779 | 83.2795 | 42.4152 | 87.3411 |

均为四场宏平均；实际选集是选中 Gaussian 的投影 IoU，不是3D点真值指标。
主方案 native_protected 相对 admission：响应 +6.0257pp（四升），实际 -2.0719pp
（三降一升，四场配对 bootstrap 95%区间[-4.5465,+0.4027]pp），P -3.7917pp、R +3.1813pp。
相对同保护的 pooled 接受，实际仍 -1.3963pp。原来13/68查询没有区域被接受，
原生接受降为0/68，但增加接受并没有恢复身份精度。

保护本身在 native 条件下使实际再降0.6910pp；P四场都降，R四场都升。
这支持“保护了身份不够可靠的正证据”的判断，不能把它当成已迁移完整实例保护。
也不能据此证明理想单场架构或原生区域函数没有价值；当前接受与成员更新组合未通过。

共1224查询—视图对，459个有检测。以下只在这些有检测对上计算，先场内均值，再四场宏平均：

| 相同接受区域的 margin 加权混合 | 48.9494 |
| 检测辅助选择的最佳单区域 | 76.4779 |
| 检测辅助贪心组合，可达到的结果 | 84.7994 |

全部候选覆盖的检测前景比例94.0839%，不计精度，不能视为好选集。
贪心组合不是全局最优/模型上界，也不是部署模型成绩；这些都是源教师一致性，
不是目标精度或3D完整实例真值。它们表明在这批匹配源视图上，已有候选可以更好地
表示检测结果，当前接受函数没有提取出这份能力；不能据此排除其他场景/未知域的候选容量问题。

765个空检测对中368个仍接受区域；459个有检测对中71个没有接受区域。空检测可能
是教师漏检，v10通常将其当未知，不能称为真实负样本或把368直接计为真实误检。
后续必须区别支持、可靠排除与证据不足，不能把空检测统一作为负监督。

## 收敛决策

1. **停止阈值、温度和无条件并集搜索。** 原生描述子保留不等于条件检测/实例接受功能保留。
2. 同视图“正证据取并、负证据必须共同成立”的场内边际算子已实现并通过两个单测，
   包括两个正确但不重叠部分在混合下相互抵消的反例。尚未接入公共推理API或获得
   benchmark成绩。源像素直接并集四场均劣于混合，因此暂不启动已准备的 region_union_v1
   全量跑分；不是宣称集合逻辑无效，而是不让弱接受器继续扩大误选。
3. 下一优先实验应是**源教师功能插入对照**：保持同一候选/来源/成员解码，用源教师
   支持的部分接受替换当前 cosine 接受，单独检验实际选集差距是否随之恢复。
   这是带查询条件源教师访问的诊断，必须单列信息预算，不能当标准场内推理成绩。
   当前84.8源像素可行性不能替代这一步的Gaussian/目标投影验证。
4. 若这一步能恢复范围，再把该条件接受函数迁入场内；学习目标必须覆盖对象存在性、
   部分归属和未知/可靠负证据，在独立查询/来源上验证，不得把本benchmark查询答案
   编译成模型、直接用评测query做训练或用特征MSE/训练收敛替代功能验收。
   若不能恢复，则优先查部分提升、视图覆盖和成员解码，不能继续归咎语义接受。

继续保留三教师、单Gaussian场、类型明确的查询、同一实际选集的一致2D/3D输出、
标准推理无源访问。职责边界可确定，具体可用的实例条件函数尚未确定。
没有新统一五任务结果、没有恢复完整v10性能、没有完成论文贡献闭环。

## 验证和保留失败

- 本轮相关测试44项通过；额外并集语义测试2项通过，合计46个不同测试。
- 四场旧 admission 预测/评分准确复现，字段与来源绑定通过。
- 两种接受器全部68查询的保护对照均通过**零容差单调性**；P/N质量完全相同。
  上轮失败仍保留，并非放宽门限。目标实际范围下降也不能用数值误差解释。
- figurines21查询冷启动：四种控制的选集全部精确一致；源目录Python拒绝探针通过。
  分数不是逐位一致。新 native 两组最大误差5.96e-8/3.28e-7；公共API一查询
  选集精确一致、分数误差8.94e-8。pooled_protected 最大误差1.01328e-6超过原定1e-6，
  所以**整体 numerical_passed=false**；没有改门限或重跑挑选通过结果。
  这不是全部场景、原始文本编码或操作系统隔离证明。
- GT哈希只证明本轮审计快照，不冒充历史字节哈希证明；全部场景散点/柱图已检查。
