## 从建场到评分的实际实现

机器清单：[31 个任务的实际执行计划与 13 个模块职责](2026-10-18-shared-evidence-architecture-inventory-v2.json)。
计划由真实 `PipelineConfig/build_plan` 生成，没有执行模型；不是端到端调用轨迹。

| 环节 | 已共用 | 仍专用或缺失 |
|---|---|---|
| 区域提取与编码 | 教师模块已有复用 | 各建场脚本、源帧选择、裁剪和缓存生命周期尚未统一 |
| 区域到三维 | UQIS 视图均衡归一化已抽入公共实现 | Gaussian 渲染贡献与 RGB-D 注册仍是不同适配器 |
| 观察读取 | 两类缓存共用只读校验和来源布局检查 | 原数据格式保留，旧编译缓存不具备全部来源信息 |
| 查询证据 | UQIS 四路的输入许可和合法裁剪绑定共用校验 | 文本候选、DINO 对应、SAM 修复、用户锚点仍是分类型提供器 |
| 证据处理 | 正负／未知域、稀疏投影、同视图分组及范围响应 | 身份决策和具体权重策略仍由提供器传入 |
| 响应读出 | 共用投影与部分重建算子 | 连续语义、实际选集、类别分配、学习式完整成员保留不同目标 |
| 评分与追溯 | 同队列、评分前预测封存、预算内报告和日志保留 | 各 benchmark 评分器和输入协议保持独立声明 |

五项分别消费公共输出的位置：

- **LERF 2D**：`pipeline/response.py` 编译许可和权重，`response_refinement.py` 消费公共投影形成连续响应。
- **LERF 3D**：`pipeline/subset.py` 消费公共域和投影结果；真实高斯选集渲染仍由原 gsplat 路径完成。
- **ScanNet**：`native_observation_prior.py` 用公共只读适配器／投影；仍先对区域做完整类别竞争。
  `local_element_fusion.py` 使用公共可见域和投影累计源证据。原双教师配方未替换。
- **NVOS**：v10 路径消费公共许可、权重和 Huber 重建；N14 的底层图像写回已复用同一数值求解器，
  但 N14 参考修复、输入许可和完整研究流程尚未接入新五项队列。
- **UQIS**：文本读出消费公共范围重建，图像和点成员头消费公共分组特征；其余 9 维证据、监督和阈值保留。

新增 CPU 测试受控替换公共投影／分组结果，检查上述相关读出数值是否变化，防止“只调用、不消费”。
LERF 3D 这项检查只覆盖传输内核，不等同于已验证真实选集渲染。

## 不能掩盖的建场缺口

实际读取了 ScanNet 10 景、两套教师共 **20 份编译场**，全部缺少区域来源视图和独立可见性。
旧文件有区域描述子、CSR 贡献及支持域；`supported=True` 表示存在区域贡献，不能当成独立几何可见性。
新 `CompiledRegionEvidence` 明确返回缺失状态，不根据场景顺序猜来源，不把无贡献当成负证据。

两种归一化也不是等价实现：

- Gaussian 编译场：像素重叠区域分摊 → 渲染贡献 → 元素累计贡献质量归一化。
- 注册区域地图：同视图嵌套区域分摊 → 有区域支持的视图均衡。

目前统一其读取和校验，保留各自算式。未来应优先从原区域缓存恢复可核验的来源偏移，
再补与原几何／分辨率一致的独立可见性；不能用另一分辨率的查询贡献或已有非零权重冒充。
因此，当前不能把需要完整跨视图来源的新机制直接铺到这 20 份旧缓存上。

## 本轮实现改进

1. 公共域与权重检查禁止广播产生额外观测轴，拒绝正负域形状不一致；不改变合法输入的权重。
2. 注册地图构建和成员辅助模块共用 `view_balanced_transfer`；Gaussian 编译场接入只读适配器。
3. 完整成员头新增 `--member-chunk-size`，缓存每个锚点的原生区域响应，分块构造 15 维特征并预测。
   默认关闭；所有载体元素仍被计算，保持原 checkpoint、特征顺序、dtype、阈值和锚点强制正标记。
   空区域没有合法锚点时显式返回空集合，避免在空数组上取中位数／argmin。
4. UQIS 图像只接受声明且哈希一致的公开裁剪；图像查询拒绝隐藏相机，点查询拒绝额外 RGB。
   这不把 N14 的合法目标 RGB 权限收缩成 UQIS 裁剪协议。
5. 预测在评分前封存，评分后核对未改变；保留所有被评分 UQIS 读出的哈希。
   完整阶段日志无损 gzip 保存，保留 UQIS 逐查询运行记录和执行计划。
   预算超限会使运行失败，不通过截断证据、减少候选或改变浮点精度来继续运行。

32 MiB 是每轮持久化上限，不是成员数、候选数或模型输出上限。
临时预测在所有评分、哈希核对和报告保留完成后释放；失败状态不伪装成完整验收。

## 验证结果与边界

当前验收报告：[CPU 组件审计 v5](2026-10-18-shared-core-component-audit-v5.json)。
v3 是探索性检查，v4 对应兼容性修复前的源码；后续运行只接受 v5 的当前源码绑定。

- 覆盖全部 31 个场景／任务，309 项记录的数值比较逐元素一致。
- UQIS：9 房间、每房间 3 个固定锚点，旧实现和 8192 行分块实现的完整载体概率／选集一致。
  同时校验全部 268 条公开查询权限；没有重跑图像／文本身份编码器，没有新 benchmark 分数。
- ScanNet：20 份真实编译场在固定查询向量下的新旧类别响应一致；不把测试查询向量称作真实类别编码。
- LERF／NVOS：延续每任务两帧实际掩码的许可／权重检查，真实渲染仍待 GPU 验收。
- 禁用 CUDA 后，`legacy` 和 `shared_v1` 两套配置均为 **224 passed、1 skipped**。
  跳过的是需要 CUDA/NVCC 的渲染器检查；不能把它记为通过。两次运行不是 448 项独立测试。

成员临时特征矩阵从各房间约 5.4–19.9 MB 降到 491,520 字节（8192×15×4）。
这是该矩阵的确定大小，不是整个进程的峰值内存，更不是已测得的查询加速比。

## 方法和后续工作的收敛

论文主机制仍聚焦**查询条件证据编译与响应形成**：先判断证据可对目标作出什么空间断言，
保留未知、来源和几何关系，再由符合任务输出的读出形成响应。
共同建场为这个机制提供可追溯观察；不同几何输入和归一化应披露，不能另包装成已验证的新贡献。
DINO 局部对应与 SAM 区域修复是证据提供器的能力，不是必须对每种任务调用的固定流水线。

下一步不需要等待五项完整重评才能开发，但效果验证按以下顺序收敛：

1. CPU 侧继续补建场来源与提供器权限，保存单独开关和代码版本。
2. GPU 可用时优先固定代表样本端到端检查，再做单模块小规模对照。
3. 将 N14 完整强配方接入同权限对照；不能因为 v10 接口成熟就停在较弱基线。
4. 单 SigLIP2、UQIS 裁剪 SAM、LERF 跨视图对应分别评估，不同时改变教师、归一化和成员头。
5. 冻结最终配方后再重评五项，验收性能和成本，再调整默认与论文主表。

新机制目前仍为计划项；本轮交付是架构清单、真实共用实现的完善及行为等价执行优化。
