# 查询条件贯穿区域与元素归属：方法修正及五项复验

2026-10-05。默认仍为 `configs/pipeline/system_v8.json`。本轮完成三组完整 UQIS 方法对照、另四项公开任务复验，以及八个新增独立训练域房间的确认。修正落实在实验学习头，不能把它们写成 v8 已部署的能力。

结论：恢复精确共同观测后，上一轮“排序提高但选集退化”转为小幅选集均值增益；然而场景波动仍大，四查询共同成功下降，三个候选均不升级。监督目标定义修正是必要的正确性修复，但没有产生大幅精度提升。

## 具体修正

1. **不再丢掉原有查询条件下的几何证据。** 新 `anchor_observation_evidence` 保留点击与元素在每个视角、每个嵌套掩码内的共同归属。分别表达掩码均值票、任一/全部掩码支持、粒度分歧、共同可见比例和是否有共同观测。单一视角的多个嵌套掩码共享视角权重，缺少共同可见性不被变成已知负例。旧 `anchor_membership` 原样迁入公共模块，默认读出算法未变。

2. **下游训练使用上游在未见房间的预测。** 四个按房间分组的折中，上游区域头用另18个房间拟合，向未见过的6个房间输出质量预测；元素头只读这种跨房间预测。部署仍使用24房间训练的区域头。旧上游在自身房间/折外房间的纯度、可见召回、新增元素纯度 MAE 分别为 0.171/0.196、0.113/0.129、0.212/0.240。这说明训练输入存在偏差；本轮结果不支持把它解释为性能差距的主要来源。

3. **每一级监督都指向实际点击实例。** 旧区域头只从纯度≥0.8的种子训练，并以种子占主导的实例定义目标；元素头推理却可能从混合种子启动。新头逐级保留实际点击、局部原生外观、点击到区域的几何关系，并预测种子自身的纯度，取消“种子纯度恒为1”的强制赋值。512个实际训练点击中310个种子的目标比例<0.8，216个<0.5。这个条件错位真实存在。

第一、二组沿用旧区域目标以做控制；第三组才修正区域目标及种子纯度。第三组区域训练为9645对，旧区域头为57560对，不能说区域训练样本数量完全相同。所有组的元素训练均为887126个样本，64棵树/最多512叶，不新增benchmark视图、教师或推理候选上限。

## 误选与漏选说明了什么

模型确实补回了更多目标，但成员判别仍不可靠：

|实际点选集|2D纯度|2D覆盖|3D纯度|3D覆盖|
|---|---:|---:|---:|---:|
|默认v8|80.06|48.52|80.35|47.73|
|A：共同观测证据|69.46|58.03|70.16|57.33|
|B：A + 上游跨房间预测|68.59|58.42|69.26|57.39|
|C：B + 逐级实际点击目标|70.62|57.41|71.97|56.28|

C相对v8新增的元素中，按每景汇总后平均约53%是真目标；共同保留的元素约86%是真目标。C移除元素中仍有约45%/51%是真目标。这些都是预测完成后的诊断，不是训练标签或推理规则。C选集以目标为唯一主导实例的数量为56/57，v8为57/58。即使点击条件正确，输出集合仍可能混入另一个对象。

因此不能把AP约10个百分点的提高写成对象提取同等提高，也不能用新AP与旧选集IoU拼成一个已经成功的新解码器。当前残余问题是对补全范围内具体元素的归属判别；区域质量标量、距离和外观相似度尚不足以稳定分离混合范围。真实/合成观测差异和空间边界表达也尚未被完整分责。

## 收敛决定与复现

保留v8为唯一默认。C作为目标定义一致的研究实现保留，A/B作为控制；三者都没有通过稳定实际选集改善及四查询共同成功的门槛。本轮停止这组统计头及阈值探索。后续重点是独立完整实例监督与实际新增元素的空间/身份边界判别，而不是继续增加区域质量标量或在这些开发场景调阈值。

同一共同架构保持：冻结几何、原生教师特征、显式归属/可见性、按目标类型读出集合。UQIS查询仍严格不读源RGB/深度/SAM；类别集合不能套用“其他实例全为负”的监督。额外3D标注属于独立声明的监督条件，候选额外局部表面数组仍比v8多2851.435MiB（本轮复用），不是紧凑学生。
