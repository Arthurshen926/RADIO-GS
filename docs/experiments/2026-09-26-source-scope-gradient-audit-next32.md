# 范围头梯度截断：真实存在，但不是已证明的首要瓶颈

本轮只读检查当前保留主线的 figurines 与 ScanNet scene0000_00，没有训练、修改地图或访问 benchmark 标签。范围头把无界线性值与残差相加，当作概率裁剪到 `[1e-6, 1-1e-6]`，再转成 logit。**错误元素若落在裁剪区间外，对自身原始输出的直接梯度确实为零。** 实测存在这样的源侧错误，值得有界修复；目前证据不支持把它解释为整个系统精度低的主因。

## 实现与反例

`radio_gs/models/grounded_semantic_transfer.py` 的非隐藏层分支执行 `logit(clamp(raw))`。`scripts/audits/train_rendered_extent.py` 同样直接裁剪 raw 概率。合成反例调用真实 `GroundedSemanticTransfer`：原始输出 `[-0.2, 1.2]`，期望目标 `[1, 0]`，预测约 `[1e-6, 0.999999]`；二元交叉熵反传后两个 bias 梯度均为 **0**。

这不等于元素永远无法修正：解码器参数由所有元素共享，其他未饱和元素的梯度仍能移动它。零梯度描述的是该错误观测自己的直接纠正信号，不是优化轨迹的不可达性证明。

当前两个父模型都采用 64 原生语义坐标 +32 结构坐标、线性概率头与256维残差。原生坐标、几何和查询编码器冻结。源概念通过路由后读取概率头；其他查询的 `native_bounded_extent` 分支使用硬范围和原生分数。这些硬路由本来就是保护原生能力的推理策略，不能把它们称为可微的端到端选择器。

## 固定源侧检查

检查前固定：每场景取已注册训练视角的前2个和后2个；按源记录顺序，每视角取前8个不同范围，置信度≥0.7、掩码面积≥20；同词掩码取并集，完全相同范围去重。每场32个范围，未根据错误大小挑例。使用原有稀疏合成权重、观测质量分母及有效像素判断。

以下“漏检/误检”仅相对**源教师伪掩码**，不代表已验证物体真值。尤其掩码外区域不一定是真负例。样本中有 `blue sky`、`birds`、`blur of trees` 等源短语，本检查没有验证其物理对象意义。

| 固定源侧量 | figurines | scene0000_00 |
| --- | ---: | ---: |
| 检查范围数 / 唯一查询数 | 32 /24 | 32 /26 |
| 实际使用可微概念头的范围数 | 32 | 29 |
| 概念头概率与正式模型读出最大误差 | 5.96e-8 | 8.94e-8 |
| 可微范围的漏检像素 | 1,033 | 1,540 |
| 可微范围的误检像素 | 5,159 | 11,644 |
| 漏检像素中，低端裁剪元素的平均渲染权重 | 10.68% | 23.58% |
| 误检像素中，高端裁剪元素的平均渲染权重 | 16.55% | 16.21% |
| 漏检中超过一半权重被低端裁剪的像素 | 82（7.94%） | 235（15.26%） |
| 误检中超过一半权重被高端裁剪的像素 | 784（15.20%） | 1,580（13.57%） |
| 全部支持正像素中的低端裁剪平均权重 | 1.443% | 1.443% |

这里统计的是**渲染贡献权重**，不是简单数场景中多少背景元素等于零。两场均有部分真实的源监督冲突处在死梯度区，但大多数错误像素仍不是由这些元素占主要权重。

ScanNet另有3个范围不经过可微概念头：`clock`（未接受范围，回退原生）、`blur of trees` 与 `close up a window`（原生加硬范围）。它们分别有153、162、1,176个源掩码漏检像素；这些数字单独保留，没有混入表中范围头裁剪统计。仅继续训练概念概率头，不能直接优化这些硬选择分支。

选中元素训练的连续 opacity gate `clamp((q-.25)/.5,0,1)` 还会进一步截断该项的梯度。漏检像素中处于低端平坦区的贡献为36.61%/56.27%；误检高端平坦区为38.50%/43.23%。这是**选中元素损失这一项**的性质；并行的全场概率损失在 `0<raw<1` 内仍可提供梯度，不能误称整个训练梯度为零。

## 结论与有界修复条件

1. 明确存在一个优化局限：把无界输出当概率后硬裁剪，会丢掉部分需要纠正的信号。它比只统计零背景更有证据，但本轮不足以证明其主导 benchmark 误差。
2. 不应直接把 `clamp(raw)` 换成 `sigmoid(raw)`：原始值0会从近零变成0.5，破坏已保留预测和范围，不能视为等价修复。
3. 候选应固定几何、原生语义及起始实际概率，做同预算源侧对照；可研究保留父概率的可学习 logit 修正，或明确声明梯度近似的裁剪训练。都须检查是否真的减少当前错误饱和贡献，同时保持完整概率渲染、硬选中元素输出和原生能力。不能只看裁剪比例下降。
4. 未接受概念的硬范围选择，是另一个明确限制；需要独立的对象对应与身份监督，不能指望普通 BCE 或源侧已经很高的简单两查询排序顺便解决。
5. 两场、64个源伪范围不构成全项目因果归因；不给该问题宣称“大幅提分”或预测提升幅度。

复现脚本为 `scripts/audits/audit_scope_gradient_next32.py`，分别由 `run_lerf_source_stage.py` 与 `run_scannet_source_stage.py` 的标签读取防护包装执行，GPU2仅用于只读诊断。逐范围值、架构、模型/来源/实现哈希与真实梯度反例记录在 `output/source_scope_gradient_next32/{lerf_figurines,scannet_scene0000_00}/report.json`。没有修改冻结文件，没有重新评估 benchmark。
