# NVOS：SOTA 目标、图像条件响应与三维回投

分支：`codex/tmm-query-response`。实验 N04，决策见 ADR0027。

## 目标与可调整范围

用户明确要求以 NVOS SOTA 精度为目标，允许合理调整模块和系统设计。
因此，旧实验的“不可读取目标 RGB”保留为受控输入条件，不再作为永久架构
约束。保留 query 响应优化的研究中心，不重做教师特征或压缩表征。

不能把超过本地 LUDVIG-SAM 91.2577 自动写成 SOTA：

- [LUDVIG ICCV 2025 原文](https://www.openaccess.thecvf.com/content/ICCV2025/papers/Marrie_LUDVIG_Learning-Free_Uplifting_of_2D_Visual_Features_to_Gaussian_Splatting_ICCV_2025_paper.pdf)：Table 1 中 DINOv2/SAM/SAM2 分别为 92.4/91.3/91.3；本地复现的是 SAM 路线。
- [SAGO 预印本](https://arxiv.org/html/2607.01628v1)：报告 NVOS 92.7，尚未在本项目复现。
- [VCAR 预印本](https://arxiv.org/html/2608.30870v1)：报告 93.5；其逐场景表只有一个 Horns 列，并按七场景汇总。尚未确认与本项目 horns-center/left 两任务及提示条件完全一致。

后两者作为外部追赶目标，不能在协议未对齐时直接认证全局 SOTA。文献检索
不是穷尽性排行榜核验。目标是继续提高真实能力，不以更换聚合口径追分。

## 本轮架构干预

用既有 v10 三维查询响应确定目标范围。将同一响应与两种图像成对输入
相同的冻结 SAM3 图像解码器：源视角训练得到的目标相机 RGB 渲染、真实
目标 RGB。相机、提示范围、图像尺寸、解码权重和输出阈值均相同。

范围提示使用响应 >=0.5 的像素包围盒。密集提示另外输入连续响应的
log-odds，按 SAM3 实际 288×288 提示尺寸变换；不假设旧 SAM 的 256×256。
采用单掩码输出，不读取 GT 选择候选，不新增人工点击或负向 scribble。
无前景提示则原样保留旧响应。

两种密集提示结果进一步作为新的图像证据，使用原几何上的归一化观测算子，
按置信度面积聚合到 512×384，以 v10 初始化做 120 步 Huber 回投，再实际
渲染更新后的三维响应。无证据的元素保持原值，不新增高斯或模型权重。

预先固定七组：v10、渲染 RGB+框、真实 RGB+框、渲染 RGB+密集提示、
真实 RGB+密集提示，以及后两组各自的三维回投。主要候选预先指定为
真实 RGB+密集提示+三维回投。全部 56 张响应完成后才评分。

这是**视角条件的查询响应修正**；一次目标视角写回不能被写成已实现统一
全视角三维响应。所有合法源视角还要对原教师轨迹检查一致性，区分目标
提升与源视角退化。源教师不是真值，该检查不能替代目标评估。

## 实现与评估检查

运行时逐任务检查：

1. 新鲜渲染的 v10 浮点响应及阈值后掩码与历史结果一致。
2. RGB 参数的高斯位置、旋转、尺度和透明度与语义几何逐一对应。
3. 源 RGB 训练／验证视角列表都不包含目标视角；真实 RGB 仅在明确声明的分支使用。
4. 独立贡献累积与 gsplat 透明度、归一化稀疏投影与 gsplat 响应一致。
5. 回投不改变无证据元素，不产生非有限值，图像拟合目标不升高。
6. 连续响应先双线性缩放，再用固定 0.5 阈值；完整八任务按任务等权汇总。
7. 原 GT>127 与 LUDVIG GT 最大值口径分别评分；独立混淆矩阵及 sklearn AP 复核全部分支。

首个运行在模型导入阶段发现环境不兼容：几何环境的旧 PyTorch 缺少
`torch.nn.attention`。失败发生在预测和 GT 读取之前，记录保留在 v1。
v2 使用项目已有 SAM3 环境，通过私有 tmpfs 交换图像和响应，未升级或破坏
原几何环境。两个环境不共享 GPU 张量或模型二进制。

## 复跑与存储

入口：`scripts/research/run_tmm_nvos_image_response.py`；SAM3 子进程由
`scripts/research/decode_tmm_nvos_image_response.py` 执行。完整配方在
`configs/research/nvos_image_response.json`。必须指定未使用的新运行名：

```bash
CUDA_VISIBLE_DEVICES=1 PYTHONPATH=.:/root/external/sam3 \
OMP_NUM_THREADS=4 OPENBLAS_NUM_THREADS=1 \
/root/miniconda3/envs/cybersim_agent/bin/python \
scripts/research/run_tmm_nvos_image_response.py --run nvos_image_response_replay_unique
```

推理用原始教师、几何、颜色参数与历史查询响应；不复制其权重。预测临时
保留在私有 tmpfs，评分结束释放。持久记录包含源码快照、配方、输入哈希、
逐任务指标及小型空间误差图。其他四个 benchmark 只绑定原结果，不计为新推理。

## 完整八任务结果

| 固定规则 | 原 GT IoU | LUDVIG GT IoU |
|---|---:|---:|
| v10 | 86.5134 | 86.6835 |
| 渲染 RGB+框 | 81.0843 | 81.2371 |
| 真实 RGB+框 | 82.4345 | 82.4817 |
| 渲染 RGB+密集提示 | 87.5575 | 87.7622 |
| 真实 RGB+密集提示 | 89.0636 | 89.1298 |
| 渲染 RGB+密集提示+3D | 86.9242 | 87.1595 |
| **真实 RGB+密集提示+3D（主要候选）** | **88.3201** | **88.4991** |

主要候选比 v10 高 1.8067 pp，比旧最佳源端候选 N01 高 0.5425 pp，
提升 6/8 个任务；flower 和 fortress 下降。真实 RGB 相对匹配的渲染 RGB
在三维输出上带来 1.3959 pp，在图像输出上带来 1.5062 pp。这是固定
解码器与提示下的输入干预效应，不是对 LUDVIG 整个差距的因果分解。

三维回投相对直接图像输出损失 0.7435 pp，说明还存在证据运输／聚合、
几何、拟合目标及读出方面的损失，尚不能仅归因于几何质量。
原 GT 下 v10 AP 为 98.0222，图像密集候选约 95.0392，三维候选约
96.3108。**IoU 提升但 AP 下降**，不能宣称全指标同时恢复。

完整空间图与逐任务整数计数在 `nvos_image_response_spatial_v2`；论文
反馈在 `paper/tmm_response/nvos_image_response_feedback.json`。源教师
平均 Huber 残差逐任务记录，回投后总体增大。该轨迹教师可能不完整，
故不能直接判定真实源视角退化，但目前也不能主张跨视角一致性改善。
这组候选使用目标 RGB，不能并入“不使用目标 RGB”的旧结果。

## 运行故障修复与完整复跑

v2 的私有 tmpfs 路径保护修复发生在初始源码快照之后。虽然未改变数值
公式，不能把 v2 标为精确源码可复跑记录；其例外明确保存在
`provenance_exception.json`。随后 v3 用完整固定源码重跑全部 56 张预测，
逐个子进程校验实际源码哈希，v3 才是登记的正式实验。

两次预测逐数组比较：40/56 浮点哈希完全一致；其余 16 张均为三维回投，
最大差值 1.87755e-6。全部 56 张在原输出尺寸和最终 GT 评分尺寸上，
0.5 阈值后的掩码变化像素都为 0。不是声称浮点逐位可重复。
比较记录绑定两次完整封存哈希，保存在 v3 的 `replay_comparison.json`。

实际模型接口核查确认：RGB 为整帧方形变换；点和框按原图宽高归一化；
密集提示不再被官方接口重复缩放。因此当前 288×288 提示与原相机
坐标处理一致，未发现宽高交换或重复缩放问题。

当前证据支持图像条件响应修正的收益，但尚未达到已核验的外部高分。
下一步按完整队列分析身份保持、缺失范围补全和三维回投损失，不能通过
GT 选单任务最佳规则，或把二维直接输出冒充三维渲染结果。
