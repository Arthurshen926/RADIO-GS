# UQIS：旧协议的合理性与现有数据可用性

日期：2026-10-04。用户明确保留旧协议：查询时只有固定地图／特征场和该模态允许的 query，不读取源照片；2D 点仅带相机几何和像素坐标，不增加 RGB/SAM 输入。

结论：**任务框架合理，现有资产能够运行和复算；当前 v0.2 候选还不能直接作为质量已确认的正式统一查询基准。主要问题是文本分组和查询构造，不是指标计算。** 本轮没有改写冻结查询、标签、旧预测或阈值，也没有训练新模型。

## 保留的任务合约

| 环节／模态 | 允许的信息 | 输出与边界 |
|---|---|---|
| 建图 | 查询视图及邻域被排除后的合法观测；所用 RGB、深度、外部几何须明确为同一比较轨道 | 每个场景先构建固定地图；不能按 query 重建或积累目标身份 |
| text | 场景 ID、自然语言指代表达 | 指向某一个实例，不是同类别所有对象的并集 |
| image | 场景 ID、224×224 参考裁剪 | 参考裁剪是 query 本身；不开放源图库、源帧编号、bbox 或相机姿态 |
| point_2d | 场景 ID、相机内外参、栅格尺寸、一个正像素 | 从已有场沿射线读取；不读取捕获的 RGB/深度，不增加 SAM |
| point_3d | 场景 ID、一个世界坐标正点 | 与 2D 点击配对的同一物理目标 |
| 评估 | 私有目标身份和官方实例标签 | 四类输出均为官方 ScanNet mesh 上同序的 V 维分数／概率 |

“无源图”限制查询阶段，不禁止在合法建图阶段使用照片，也不禁止 image query 自带的裁剪。地图自己的渲染状态可以用于定位；不能借地图缓存名称重新引入源照片检测、跟踪或目标答案。

公开 mesh XYZ 是旧协议已有的输出域信息，实例 ID 不给方法。若另行提供完整网格用于建图，必须明确它是额外几何先验并对所有方法公平提供；不要将此结果称为 RGB-only 重建。

这套定义适合比较四种输入下的**单实例三维集合召回**。它没有整体／部件层级标签、同类全实例查询、多点／负点交互轨迹，不能单凭四个模态名称宣称已验证这些额外能力。

## 需要先解决的实质问题

### 1. Core 的“无需关系推理”定义没有落实

`construction.py::select_profiled_expression` 把 `uses_spatial_lang=false` 等同于无需关系推理。实际检查31条 Core 表达，**至少25条明确含有空间关系或比较：16条空间关系、9条比较**。

例如：

- `The bed closer to the windows.`
- `The shelf next to the couch.`
- `smaller of the two chalkboards.`
- `The shortest chair with wooden armrests`

这是助手对实际文本内容的检查，不是新增独立人工标注。“含比较”也不意味着每一条只能靠比较才能识别；但它足以否定“这个子集保证没有关系／比较”的解释。剩余6条也未被认证为绝对无歧义。

解决：保留旧31/36划分和旧成绩作为历史版本，不再解释为经过验证的能力分解。新版本逐条核验属性、空间、比较、否定／指代歧义，四模态在同一目标集合上分别报告；关系子集作为额外分层。不能根据某个方法的成绩决定移动或删除查询。

### 2. 点提示构造缺少逐像素三维对应约束

67个2D／3D配对点的最大重投影误差仅0.000227像素，但这只说明两者使用同一份深度。对照官方目标几何：

| 场景／实例 | 原点距目标三角面的最近距离 | 判断 |
|---|---:|---|
| scene0249_00 /22，board | 39.24cm | 明显不在目标表面 |
| scene0249_00 /35，window | 39.08cm | 明显不在目标表面 |
| scene0249_00 /37，trash can | 15.05cm | 最近网格实例还是另一个实例 |
| scene0704_00 /6，cabinets | 5.30cm | 较小偏差，需按深度／网格容差处理，不能与前三例等同 |

其余点的整体最近目标顶点距离中位数为1.17cm，90分位为2.44cm。三角面距离复核排除了前三例只是顶点采样稀疏的解释。

根因有两层：

1. `derive_paired_point_prompt` 支持 `valid_correspondence`，但 `official_constructor.py` 实际调用未传入它。掩码整体投影纯度较高，不能保证选中的那个深度像素对应目标。
2. `select_interior_pixel` 对未补背景边框的掩码直接做距离变换，未把图像边缘作为边界。实际18/67点距图像边缘不足5px，其中14个恰好在边缘，不能概括成稳健的内部点击。

解决：在构建器内部同时要求目标掩码、有效深度、目标表面对应和边界余量，再成对生成2D／3D点；构建器使用GT合法，但GT不能进入方法输入。只在3D中吸附旧点会破坏2D／3D配对，不能这样修。

同帧小诊断发现：board和trash can能找到符合5cm几何约束的其他像素；window在该查询帧没有这样的像素。后者应重新选择合格查询帧，再统一更新 image、两类point和建图排除集合，不能仅在评估时丢掉坏点。上述候选检查未写回冻结版本；还需把边界约束一起实施。

### 3. 图像查询只按可见面积选帧，未保证实际可辨识性

查看全部67张裁剪后，发现若干明显运动模糊／过曝样例，例如scene0249的board/trash can、scene0435的lamp、scene0203的部分couch/pillow。还存在多个相似实例共现、背景占据很大比例的参考裁剪。

旧构造在最多3个共享查询帧的约束下偏好可见像素数；面积大不等于参考图清晰，也不等于能凭裁剪辨认具体实例。自然困难样本可以保留，但不能把查询本身缺少区分信息都解释为场特征能力不足。

解决：在不参考模型成绩的前提下检查清晰度、曝光、目标占比、遮挡和实例可辨识性；保留难度标签，必要时换同目标的合法参考帧。先明确3个共享查询帧是否仍有必要，它不是四query任务的本质要求。若改帧，所有配对查询与排除集必须一起更新。

### 4. 排序指标可用，实际集合指标尚缺独立校准

AP、固定IoU、oracle IoU的实现和聚合没有发现计算错误。低UQ-Mask不能全归因于校准，但也不能把未校准相似度的0.5截断直接当成已验证的实例选择能力。

保留每模态AP；在独立开发场景固定相似度到概率／集合的读出，再报告每模态固定IoU。Oracle IoU只诊断排序中可达到的边界，不能成为实际方法成绩。四模态均值不能替代各自分数。

## 可用性边界与接入当前主线

- 现有候选数据、官方GT、查询裁剪、历史地图与预测可用于开发和复算。全部9份原始 `.sens` 和网格标注可读，恢复建图不依赖源图查询权限。
- 原查询帧导出仅找到4场景／29目标可直接重放；其深度生成的点与旧记录最大差不足1e-5米。其中6张裁剪逐像素相等，另23张与当前导出RGB重裁的平均通道差为0.41～3.41/255，不能宣称像素级复建已全部通过。5场景的旧导出不在已知位置，6场景的原2D-instance ZIP仍返回权限错误；完整重新构建查询还需解决这些依赖。评估已有固定查询不需要这些私有构建输入。
- v0.2仍以v0.1的mesh／配对清单加新的text profile组合；**21条文本内容改变但query ID延用**。复跑必须使用v0.2文本清单，不能按query ID复用v0.1答案。新版本应绑定表达内容／版本，提供一个明确入口。
- 9个场景历史结果已打开，不应再宣称盲测。它们可作为公开固定开发基准；校准和泛化验证应有不同场景。无需为此继续堆叠复杂封存服务。
- 当前RADIO-GS的`--access map-only`已具备四种入口，但image／point主要是相似性排序，尚非经过本benchmark验证的实例集合。当前较强的source-assisted检测／跟踪路径不能用于这条严格轨道；其公共benchmark成绩不能直接搬来证明UQIS。
- 旧LUDVIG对照使用CLIP和DINO两套场；可以作为合法比较方法，但必须披露多场成本。RADIO-GS若要支撑单一统一场主张，四类query必须读取同一张冻结地图，不能拼接分支最佳结果。

## 最小后续顺序

1. 保持旧模态输入合约；冻结v0.2为历史候选，先修查询构造的三维对应、图像边界与参考图质量。
2. 核验文本能力标签及指代歧义，导出一个清晰的新版本；不能偷偷改变旧版本的分数含义。
3. 在独立开发场景固定集合读出／校准，保留各模态AP和IoU。
4. 用同一新建地图跑四query；严格关闭源辅助路径，先验证真实输出是官方mesh上的同一目标实例，再扩展完整对照。
