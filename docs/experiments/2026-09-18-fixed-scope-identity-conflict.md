# 固定范围头的身份冲突：当前 V2 的直接反例与否决对照

## 直接证据

助手审阅的源场景袋子 `plastic bag` 被路由至 `plastic container`，接受分数0.8693。该范围头来自13个视角，而袋子精确短语仅有一个源视角检测。在同一个 frame174，两个教师mask分别528/417像素，交集0；完整模型却给两条query输出**完全相同**的元素概率（最大差0）。

这不是“源监督还不够多”可以单独解释的问题。两条query被强制使用同一个范围函数，模型不可能同时准确表达这两个互斥目标。重复训练共享范围头只能折中，不能让相同函数同时变成两个对象。该反例使用源侧伪mask和助手身份审阅，不是精确人工边界真值；未用于训练。

另有33.32%的袋子正证据贡献落在范围概率硬截断的下界，梯度为零；98.76%低于0.5范围阈值。硬截断会妨碍纠错，但约三分之二正贡献仍有梯度，不能把全部失败归因于梯度。

## 冻结场对照

对两个场景统一禁用所有词语原型的强制接管（接受阈值置为余弦不可达到的2），采用原先已经存在的原生支持与结构范围重叠选择路径。所有其他张量保持原样，无单query例外、无新训练、无额外gate。该机制在旧版本已试过，此处是当前V2上的对应反例与完整回归复验，不宣称发明新方案。

袋子三个源视角IoU：原生文本70.495%，V2完整0.029%，统一取消强制接管后81.859%。证明至少该对象的正确结构候选和可用原生身份信息已存在，损失发生在接管路由。

但全场标注开发评价：

|方式|figurines文本IoU/AP|ramen文本IoU/AP|
|---|---|---|
|V2完整|43.812 /60.083|33.474 /50.874|
|统一原生范围选择|43.899 /61.235|21.226 /49.333|

因此**否决统一替换**。不能用源袋子的巨大增益遮蔽ramen的12.25个百分点IoU退化。图像和提示分支不变，完整参考任务复验另行封存。

## 对后续修复的约束

1. 接受的词语概念不能被视为已经验证的对象对应；尤其不能把未进入多视角词表的query吸附到一个不相容范围。
2. 同视角不相容范围必须进入实际query的训练/验证约束。继续只训练固定范围头，即使全部源范围遍历，也不能消除函数相同的结构限制。
3. 不能统一移除受监督范围能力：ramen的原生支持仍不可靠。需要同时解决query身份绑定与原生弱响应下的合法范围补全。现有插值式query修正尚未证明做到这一点。
4. 源查询身份碰撞、保持query区别和完整基准回归必须同时验收；只看平均源mask拟合会漏掉这一反例。
