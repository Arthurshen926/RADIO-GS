## 修复了什么

上一阶段的规则用“场景所有区域中前5%的文本相似度”否决检测实例。它把两种现象混在一起：实例真的不匹配文本；原生区域特征对该部件普遍响应较弱。bear nose因所有48个训练实例被排除而崩溃。

现在只比较**同一个查询已经检测出的实例**的原生相似度。掩码IoU≥0.5建立实例与原生区域的对应；没有对应时，不虚构身份反证。对这些分数比较一个分布与两个分布：

- 单分布假设不提供“哪组身份更差”的证据，不作相对否决。
- 双分布假设中，高原生文本相似度组获得更高支持。
- 用BIC近似模型证据加权两种假设；支持低于0.5的实例变为未知，而不是负例。
- 无足够样本/分数没有变化时保留原检测证据。没有查询名称规则、部件关键词规则、竞争查询词表或标签阈值搜索。

这是身份支持模型，**不是经过真值校准的正确率**。分组也可能反映视角变化、不同实例或裁剪差异，不能把低支持组称为已证实错误。范围仍由SAM3掩码给出，几何、原生特征、查询编码、集合求解器与评价均冻结。

新增数值核心：`radio_gs/querying/source_identity.py`。实例对应提取仍使用现有区域缓存；它增加查询时的缓存扫描与对应成本，没有新VFM调用，也不是紧凑学生训练。

## 留出对照与消融

固定每五个源视角留出一个，其他条件与上一阶段相同。模型分布只使用训练视角；本阶段没有对留出教师或标注调阈值。地图仍使用全部源图，因此不是独立场景泛化。

|条件|集合IoU|留出教师IoU|
|---|---:|---:|
|固定集合优化对照|63.94|72.96|
|上一阶段全场景分数门槛修订|64.86|74.34|
|新条件化身份核对|66.30|70.62|
|强制所有查询分成两组|65.74|69.93|

新机制提高2.36pp，但留出教师一致性下降。原教师本身存在身份错误，因此不应以更贴合它作为唯一验收标准。留出与标注的视角/聚合不同，不能由差值分配误差责任比例。

单/双分布证据比较相对强制分组提高0.55pp。强制分组使yellow desk84.64→25.21%；允许不否决的版本避免该次崩溃。这提供了“不应强行分类身份不确定候选”的受控证据，但尚不证明这种统计方法的独立新颖性。

新机制的鼻子留出结果82.38%，对照79.36；此前修订仍只有20.52。本次修复不是靠检测部件名称或给鼻子单独放行。

## 入口与复现

默认配方仍为`configs/recipes/current_research.json`，现在默认profile为`identity`。`source`是原固定对照；`map`、`regional`、`calibration`继续作为单独对照，不拼接其最好列。原生身份与区域跟踪尚未联合验证，运行参数明确互斥。

```bash
# 默认新文本主线；先查看实际命令：
python scripts/research/run_current_research.py --scene all --evaluate --output output/current_identity_rebuild --plan
# 去掉--plan即可执行；旧对照用--profile source。

# 重复留出对照和强制分组消融：
PYTHONPATH=. /root/miniconda3/envs/cybersim_agent/bin/python scripts/research/run_conditioned_identity.py --output output/conditioned_identity_replay
```

完整源实验实际调用`run_consolidated_query.py --native-identity`，显式复用先前冻结的原生查询响应与原始SAM3输出，只重新提取身份对应、推断与拟合集合后评分；没有重跑编码器/检测器、没有重建地图、没有读取父版本集合答案。其逐场景精确命令存于`output/conditioned_identity/full_source/<scene>/commands.json`。默认入口可从当前query重新生成上述响应与检测。

统一结果：`output/conditioned_identity/summary.json`。汇总脚本：`scripts/research/summarize_conditioned_identity.py`。配方：[conditioned_identity.json](../../configs/recipes/conditioned_identity.json)。此处只记录本轮实测，并不把计划打印称作另一次全新模型运行。

## 是否已经是一套完整有效的系统

|层面|当前真实状态|
|---|---|
|已有地图的文本查询闭环|已完成统一入口与完整重算；本轮新身份机制已在入口中实跑四场景|
|主线方法|冻结原生语义地图→当前文本→源实例检测→原生身份支持→未知区保留→实际集合优化；语义与集合输出分离|
|无需额外源图的地图查询|有独立map配置；不能享用identity的在线成绩|
|图像、2D提示、3D提示|历史路径仍在，尚未在本轮同一地图和新身份/范围逻辑下完整验收|
|NVOS、ScanNet OVS|仍是已有独立参考路线和协议限制；本轮没有新的统一入口结果|
|LERF独立三维、公平公开SOTA|未完成；现有selected指标是选取后的二维投影|
|新场景泛化、统一紧凑学生|未完成；当前高容量特征和源缓存不能被称为紧凑部署|
|UQIS|按用户要求继续暂停|

因此，**已经有一套可运行且在文本开发评估上有效的主线，不再只是互不相连的个例结果；尚不是完成最初全部目标的统一系统。**

下一阶段应在保留新文本对照的基础上，补齐身份不确定时的多实例/部件范围合约，并将参考图/提示的实例锚点接到同一集合求解器。不要再靠全场景相似度阈值或查询名补丁处理bag；先确认单实例、同类集合和图案/部件三种范围的关系。与此同时，需要未调参场景与相同访问权限的强基线，才能推进贡献及SOTA结论。新增公开排名、四query、紧凑部署仍须分别验证，不能因文本默认晋级而视作完成。
