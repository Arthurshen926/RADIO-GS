## 实际改了什么

上一组 Soft 保留了更多目标关系坐标，但全部8组 NVOS 的正、负支持在关联阶段都
没有通过多数门槛，59个正确 UQIS 点支持中也有19个完全未接通关系证据。这是实际
查询函数缺失，不能以保留张量或训练收敛解释为已迁移能力。

本轮直接改变支持到关系的函数。对每个已观测支持分量 i、源区域 r，保留正证据
`p_ir`、排除证据 `n_ir` 与未知。满足 `p_ir > n_ir` 且原尺度比在 `[.5,2]` 时，
以 `p_ir` 作为视图内偏好，归一化后乘该分量在该视图内最大的已接纳已知质量
`min(1,max(p_ir+n_ir))`，再按合法输入权重混合各分量。未知分量弃权，低可信
分量保留弱质量；不再先对所有射线求均值，再要求绝对正质量超过 .5。

第一个版本曾用 `p/(p+n)` 作视图内偏好。独立于任务分数的反例
`p=[1,1e-6], n=[0,0]` 产生 `[.5,.5]`，微弱区域借用了强区域的可信度。
该批次在30份构建及部分预测之后、任何评分之前停止。修正版改用 p 并重新冻结；
停止记录和部分输出保留在 `mixture_functions_v1/source_counterexample_stop.json`。
不能把停止的第一版当作另一组完整五项结果。

修正版的所有场张量与 Soft 父场逐字节相同，独立复制导出，未增加来源、教师、
标签或训练。总张量字节 **58,312,658,544**，新增字节0，仍包含不再使用的旧硬关联
坐标。目标正／排除矩阵、几何、原生描述、成员先验、有限证据更新、正负提示组合
与类型读出不变。它是未压缩的部分功能参照，不能称为完整 B、紧凑表示或已证明
的论文创新。标准运行时仅消费导出场与当前查询。

## 问题已能拆到哪些环节

**支持关联已真正接通，但强度恢复有限。** 全部8组 NVOS 正负提示均关联到了
证据，选集、成员分数、响应和保留集响应都与父场发生变化。对固定59个正确点支持：

| 诊断量 | Soft | Mixture |
|---|---:|---:|
| 有关联视图的正确支持数 | 40／59 | 55／59 |
| 平均接纳视图数 | 1.3390 | 1.9661 |
| 平均有效视图质量 | 1.3390 | 1.3711 |
| 已观测目标上的平均正质量 | .3571 | .3616 |
| 已观测目标潜在坐标覆盖 | 94.9755% | 94.9755% |
| 已观测目标实际证据激活 | 55.5853% | 72.4393% |
| 已观测目标排除占优 | 10.0394% | 16.5521% |
| 已观测目标漏选且无证据 | 29.5338% | 21.4844% |
| 已观测目标漏选但正证据占优 | 5.2008% | 8.1664% |
| 已观测目标漏选且已知证据非正占优 | 9.5115% | 14.6128% |

这些比例是正确支持的逐查询均值，分母为已观测目标；不与全 benchmark 宏平均
混用。接纳视图多了，但质量总量几乎没增加。例如 fortress 的正提示接纳9个视图，
有效质量只有 .00120；不能把“激活9视图”称为充分的正证据。

**新增证据也会反对真实目标。** 目标正负冲突比例6.7441%→9.0325%，排除占优
比例也增加。这与 SAM 部分区域及粒度不等于完整实例相容，但当前对照不能唯一
判定是区域粒度、错误对应、尺度筛选还是先前提升过程造成。必须保留共同可见、
部分掩码支持／全部掩码支持和粒度分歧，而不是把任何“该区域之外”直接升级为
完整对象反例。Soft→Mixture 在59个查询累计补入46个目标顶点、丢失144个目标
顶点，新增51个非目标、排除267个非目标；这些是按查询累计的转移计数。

**最终决策仍没有等价迁移。** 在当前 .5 阈值和单正点条件下，非硬锚点成员判定
可精确写成 `2*prior - 1 + P - N > 0`。全部67个查询的稳定行与实际选集无矛盾；
本次审计没有落入声明的 `2e-6` 数值边界。新方法在53个正确查询中有17,588个
目标顶点虽 P>N，仍不足以越过先验负余量。各查询所需倍率中位数再取中位数为
115.84，但这是代数诊断，不是建议采用该倍率，也没有据此拟合或改变模型。
同时存在错误极性的证据，盲目放大 P/N 可能放大错误。

因此这版共同成员机制依然是“既有先验 + 固定有限证据更新”。诊断算子已在二值、
可见排除互补、单锚点极限复现 v10 六项共同观测统计，但这些统计尚未进入部署的
成员判定，真实软部分观测也没有完整 v10 可见性。不能把六项统计测试通过称为
成员决策能力已经迁移。

**原生功能与预算仍不足。** 268个 UQIS 输入的原生输出逐值不变，说明这次干预
没有改变该通道，不能证明单均值 Gaussian 描述保留了完整源 patch 功能。来源清单
审计发现新路线去重30场只用了534个训练视图、60个特征开发视图，v10 声明3,286个
来源视图；分族计数见[能力账本](../method/v10-capability-transfer.md)。当前534个
训练视图全部进入关系编译；fern 原来就是12个训练视图，不是丢掉六个无效 episode。
这个差别说明当前参照不能充当同预算上限，不证明增加视图就能独自补齐精度。

UQIS 九场已验证可通过唯一 `source_vertex_ids` 与 v10 载体精确对应：七场直接
同序，两场各少三个顶点，映射后的坐标仍逐值相同。由此具备按来源顶点索引编译
完整证据的几何基础；本轮尚未实际迁移这些额外来源，也未证明监督／划分相同。

## 验证结果及明确失败项

- 51项针对函数的测试通过，包括未知／排除、分量混合、低置信区域反例、完整
  scribble 分块、CPU/CUDA、签名与推断查询的保存加载，以及二值 v10 原语对齐。
- 30份构建全部保持 Soft 张量 SHA256；1,068次独立源光栅与场内函数重放全部
  非空，最大绝对误差 `4.76837158203125e-6`，低于冻结的 `1e-5`。
  覆盖每源视图的单点与两条完整投影射线；目标行为固定512个采样载体行加全部
  查询支持行，不是遍历每个 Gaussian 的证明。
- 全部31组预测完成后才开始评分；67个真实点查询重放最大误差约 `1e-6`，
  8组 NVOS 最大误差 `1.7881393432617188e-7`。这不修改已有预测。
- **原严格冷回放失败，未更改通过标准。** 在一个真实场景的文字、图像、2D点、
  3D点和类别菜单五类检查中，只有图像分数哈希不同，全部选集完全相同。
  保持原始 GPU 操作顺序、只捕获已复制到 CPU 的哈希输入后，两次全新复制进程
  均复现1,339个图像分数条目的差异，最大 `1.7881393432617188e-7`；其它四类
  分数完全相同。另一个操作顺序的原始张量检查全部相同，不能用它覆盖原失败。
  具体导致位差的底层算子尚未定位。
- 数值补充检查沿用既有函数测试绝对容差 `1e-6`，数值与选集通过；两种冷回放
  均没有源路径打开记录。执行机制是 Python 文件打开审计，不是操作系统沙箱，
  覆盖一个场景，不能扩大为所有场景的运行时证明。

结果 JSON 显式记录 `complete=true`（执行范围）、
`strict_cold_replay_passed=false`、`numerical_cold_replay_passed=true`、
`all_validation_gates_passed=false`、`model_promotion=false`。
不为追求逐位一致而更改模型阈值或重写已评分预测。

## 下一阶段架构调整的顺序

1. **先建立合法来源足量的功能参照 B。** 清点查询无关来源，保留开发划分，取消
   中间实现任意20帧上限；用上述显式顶点映射保留同一物理载体。不能直接把 v10
   清单3,286帧全部认定为同条件可用；来源辅助、监督与输入差别逐项声明。
2. **把关系能力从两项质量推进到条件观测函数。** 保留共同可见、部分／全部支持、
   粒度分歧及符号查询语义，让这些信息真正参与同一个成员判定。先核对来源函数
   与场函数，再做足量参照与当前预算的全部任务对照；不以增加损失或调整倍率代替。
3. **分别完成原生局部功能和完整成员监督的条件对齐。** 允许多模态局部表示与
   必要的小读出，不强制保留单均值、32维分组或当前有限更新；完整实例监督若有
   额外来源必须单列，不能把部分 SAM 标签拟合视为完整对象能力。
4. 继续用一份场、共同成员机制和类型读出跑全部五项，分别报告身份、证据、实际
   选集与渲染结果。足量参照成立之后再讨论压缩与论文主张，不引入 v10 运行时
   来源库或按任务分支的旧求解器。
