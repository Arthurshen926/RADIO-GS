# 同一地图的全场概率与三维选择输出存在明显差距

此前完整开发分数采用“全场渲染语义概率，再按可观测语义质量归一化”。它不能直接代表三维元素选择后的对象范围质量。本轮冻结同一 v2 模型、原生查询编码和几何，补齐先选三维元素、再只渲染所选高斯的输出路径。

OpenGaussian 的公开 LERF 任务确实采用三维选择后投影到图像评价，而非逐高斯三维真值。参见[官方任务说明](https://github.com/yanmin-wu/OpenGaussian#44-lerf-evalution-open-vocabulary-object-selection-in-3d-space)、[官方渲染实现](https://github.com/yanmin-wu/OpenGaussian/blob/main/render_lerf_by_text.py)及[官方评分实现](https://github.com/yanmin-wu/OpenGaussian/blob/main/scripts/compute_lerf_iou.py)。仓库另一个要求逐元素真值的实验合约不能作为不执行此公开任务的理由。

## 固定合约

- 从现有场的最终文本概率按既有阈值 0.5 一次选择三维元素，所有目标视角共享这一集合；只允许已观测元素。
- 使用原几何位置、法向旋转、尺度和不透明度；非选中元素不参与遮挡，不加后处理或目标图像细化。
- 所选集合的 alpha 按 PNG 保存规则量化后，以 >10 判正，匹配公开评分器的像素阈值语义；不搜索阈值。
- 使用本地 LERF 原尺寸 polygon 并集作为目标。**未验证其与公开发布的 JPEG 目标逐像素等价，因此下列仍为开发诊断，不直接与论文公开分数比较。** 原生编码沿用已通过在线/重放一致性的内容绑定缓存；预测阶段禁止访问训练教师资产。
- 每个查询的选择先保存，再使用目标 mask 评分。不是根据目标视角重新选择，不是体积三维 IoU。

## 匹配分辨率的结果

| 固定输出路径，IoU% | figurines（56项） | ramen（71项） |
|---|---:|---:|
| 原全场连续概率，原尺寸 | 44.06 | 32.92 |
| 同一三维二值选择，全场遮挡下的归一化渲染 | 43.03 | 33.03 |
| 仅渲染选择集合，alpha >0.5（固定诊断） | 33.84 | 21.99 |
| 仅渲染选择集合，公开 PNG >10 规则 | **25.55** | **18.27** |

原尺寸为 986×728 / 988×731。先前 480 像素宽的全场分数是 43.81/33.47%，分辨率不是上述大幅差距的主要解释。三维二值化后在原全场渲染中也没有产生相近幅度的下降。

公开像素规则下，选择集合的投影 precision/recall 为 25.75/91.58% 与 18.93/75.37%；全场二值选择渲染对应 52.25/69.09% 与 38.26/64.98%。**范围外覆盖暴露得明显更多，不能把全场概率分数解释成正确的完整三维对象选择。** 去掉非目标遮挡、取消概率归一化和较低 alpha 阈值均改变输出语义；这些控制的差值不可直接相加作为因果百分比，也不能单凭它们断言几何中心位置有误。

这暴露了应当纳入主验收的问题：原训练及主要评估强调全场可见像素，而任务还要求取出独立三维集合。源侧监督需要检查选择集合的外部误检，不能仅在完整场的遮挡与归一化下得到好分数。下一步应在合法源视图上审计并训练对应输出合约，保持原全场任务并列，不能拿公开评估标签选择裁剪尺度或阈值。

## 实现和验证

新增 `evaluate_current_selected_lerf.py` 与 `diagnose_selected_lerf_rendering.py`。第二个工具读取已封存的同一三维选择，重新渲染并验证公开阈值下的所有 PNG 二值结果逐像素完全一致；所有固定诊断共用同一原尺寸目标。几何和原模型没有修改。

结果位于 `output/current_selected_lerf_20260918/{figurines,ramen}/report.json`；完整同分辨率连续输出及匹配渲染诊断位于同目录上一级。其用途是补齐系统输出合约和暴露误检，不是报告性能提升。公开 JPEG 等价验证、其他两场、ScanNet OVS 和 NVOS 完整方法仍须继续落实。

## 必须保留的语义边界

上述 false positive 是相对二维可见 polygon 定义的。独立渲染会暴露原先被其他对象挡住的表面，其中可能既有选错对象，也有正确对象的被遮挡部分。例如 bowl 的完整表面与可见碗沿并非同一个目标范围。因此分数差距不是“三维语义错误率”；仅优化独立渲染对可见 mask 的 IoU，可能鼓励删除真实对象的隐蔽部分。新训练仅为有界开发控制，不据此认证完整物理对象质量或默认替换地图。对象身份、可见范围和完整三维范围的验收仍须分开。
