# 查询条件成员判定与 v10 主线收敛

2026-10-06。全部完成：3组固定拟合、独立训练域的完整验证、31个共同配方任务。
唯一开发默认更新为`configs/pipeline/system_v10.json`；v9保留为数值对照。

**本轮兑现的是上一轮已有证据支持的图像范围收益。新的查询监督模型没有获得
稳定净增益，全部留在研究分支。不能把这两件事合并成“新训练方法提高了五项指标”。**

## 当前实际主线

共同入口`python -m radio_gs.pipeline.cohort`现在默认读取v10。
冻结几何、合法观测、原生教师空间、任务类型及评估合约继续保留。

- 文本仍使用原生整句身份与原有跨视角物理范围读出。
- 图像保持原生SigLIP和局部DINO对应排序，选中区域后估计几何锚点，
  调用现有完整载体成员模型。
- 2D/3D真实点保持原有输入与同一个成员模型。UQIS的2D点只读像素和相机，
  不增加RGB、深度或SAM权限。
- 该成员模型仍只用22个独立房间的官方3D实例标签、真实注册观测训练，
  阈值仍为独立校准确定的0.35。本轮失败的NR3D查询监督不属于v10训练条件。
- LERF、NVOS、ScanNet保留各自类别集合、参考实例或类别分区的读出与输入轨道。

同一张地图支持四类查询，但文本尚未统一到这个成员解码器。图像的估计点仍有
身份不确定性；这是一项经过开发验证的近似，不是已经完成联合不确定性推断。

## 本轮方法研究：纠正查询条件

上一轮范围复用把文本/图像压成估计点，再调用只用真实正点训练的成员模型。
本轮训练数据证实这个条件差异很大：1377条自然指代查询中，估计点只有263个落在
目标实例，980个落在其他有标签实例，134个落在未标注元素。后者没有作为负例训练。

新增`QueryMembershipEvidence`与`QueryConditionedMembership`：

1. 监督对象明确为查询实际指向的实例，估计点和源区域都不强制为正。
2. 保持原生完整表达和教师坐标；同一原生排序选择同一源区域和中位数锚点。
3. 新证据保留全部区域响应、区域/视图排名、相对响应、按视图平衡的软成员支持、
   视图间分歧和查询响应的不确定性统计。可见区域的软补集只是输入，不是真负标签。
4. 图像选区的跨教师融合排名与原生余弦是两种量。接口分别传递它们：前者维持
   原图像身份选择，后者才进入与训练含义一致的查询证据通道。此研究接口未部署到v10。

最初两组严格配对：相同22个真实训练房间、1377条表达、2,578,504个采样元素、
同一64棵树/每树最多512叶的学习器。一组只有原锚点特征，一组再增加查询证据。
每查询正负样本各最多1024，权重恢复实际元素质量；这是训练计算预算，未限制
源帧、区域候选或评估元素。训练未知标签不进入损失，评估仍消费完整载体。

在第一组开发结果不稳定后，只补了一个结构消融：同时删除锚点位置、锚点外观、
锚点共成员和所选区域成员特征，完全由查询证据决定选集。没有继续扫损失或容量。
以上均使用相同22/3/4训练/校准/开发划分；4个开发房间此前已多次使用，非独立最终测试。

## 校准完整范围后，新模型仍未胜出

最初沿用0.05间隔的校准网格。无锚点消融的最优网格点为下边界0.05，因此没有
直接据此给方法定案。随后固定全部模型，在三个校准房间的207条查询、全部元素
分数上合并实际IoU断点，求每模型唯一全局最优切点；无概率下限、无阈值网格，
不使用开发或benchmark标签选择切点。原检查点和精确校准检查点分开保存。

| 175条完整开发查询，实际IoU | 网格校准 | 最终精确校准 |
|---|---:|---:|
| 旧估计锚点桥接，原固定阈值 | 7.0088% | 同左 |
| 查询真值监督，只保留锚点特征 | 6.4939% | 6.4847% |
| 查询真值监督，锚点+查询证据 | 6.6475% | 6.8550% |
| 查询真值监督，完全去掉锚点 | 6.7142% | 6.6060% |

精确阈值依次为0.095868、0.137625、0.064491。无锚点最优点实际在原网格两点之间；
取消网格并未改变失败结论。两种机制都未通过“比旧桥接和监督控制各高2pp，且至少
3/4景不退化”的既定门槛，未扩展这些新头的benchmark执行，也未部署。

保留查询证据的模型，将查询证据换成该场景查询均值后降到1.9121%；无锚点模型
相应降到2.2848%。查询信息确实被使用，不能说模型完全忽略了query。查询均值
访问整个开发查询集合，仅用于干预诊断，绝不是允许的自动推理输入。

## 更具体的瓶颈

在估计点没有落在目标的145条查询上，旧桥接IoU为1.9878%，查询证据模型4.2247%，
无锚点模型5.0018%。但在估计点正确的30条上，旧桥接48.3737%，查询证据模型
29.5282%，无锚点模型21.6402%。这里是各条件子集的场景宏平均；没有该子集的
房间不进入该条件均值，不能用这两行直接加权复算总体。

修正监督并降低错误身份的确信度，有助于部分错误案例，却没有可靠识别哪些
估计身份正确，导致已有正确案例的条件解码能力显著损失。无锚点模型总体覆盖
升到28.4771%，纯度只有7.9510%，说明扩大软范围也不能代替身份证据。

新增分支读取的是原生整句在各区域上的相似度及其统计，并没有建立目标、属性、
参照物关系的独立组合证据。因此“保留查询响应”仍不等于“理解并绑定所指实例”。
这些对照只否定本轮统计特征+固定容量分类器的修复方案，不证明所有查询条件学习
或不确定性建模都无效，也不能把剩余损失全部归给原教师。

## 后续只集中一个主问题

保留已验证的条件成员解码，单独解决“查询对应哪个物理实例/范围假设”，再让
条件解码按这个身份工作。身份证据需要实际参与目标、属性和参照关系的区分；
同类竞争、查询/关系干预和真实选集都要检验。不要再通过混合正确/错误锚点标签，
期待同一个局部成员头自动修复身份；也不继续本轮树容量、统计特征或阈值扫描。

共同架构维持原生教师→合法观测→按查询/集合类型解码。当前实例指代诊断并不
证明五项benchmark拥有完全相同的数值瓶颈。v10是有验证依据的组件整合，距离
统一高精度、可压缩多模态场和论文核心机制证据仍有缺口。
