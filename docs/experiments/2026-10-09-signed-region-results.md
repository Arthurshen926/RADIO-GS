# 显式正负区域条件：完整八例结果与失败归因

主方案未恢复范围，不提升默认。科学实现冻结于 `ffe6bb6`，同七个场、八个
NVOS 请求、旧120个来源；24份预测全部封存后才评分八例。无训练、额外场状态、
新增标签或运行时源图像。重新预测的 parent 与原保留结果八例完全一致。

| 固定条件 | 响应IoU % | 实际选集IoU % | 精确率 % | 召回率 % |
|---|---:|---:|---:|---:|
| parent | 61.8552 | 69.7200 | 91.9179 | 76.7605 |
| joint_unsigned | 61.8458 | 69.6806 | 91.8704 | 76.7625 |
| joint_signed（预定主方案） | 61.8454 | 69.6806 | 91.8704 | 76.7625 |

joint_unsigned 固定未增强成员先验，显式融合正区域证据；joint_signed 再将
区域关联质量改为 max(C+−C−,0)，未知弃权，排除后不重新归一化。主方案实际
IoU变化−0.0393pp，按七个物理场聚类的配对bootstrap 95%区间
[−0.1361,+0.0011]pp；horns两请求属于同一场。相对unsigned，signed只提高
约0.000005pp，不能解释成有效收益。主要退化在fortress：88.2425→87.9252%。

## 到底没有解决什么

flower与orchids的实际IoU仍为23.9933%和21.0862%，选集完全未改善。
两者精确率99.6468%/98.9312%、召回24.0137%/21.1343%，给定正涂鸦覆盖仅
41.5833%/45.6333%，负涂鸦误覆盖均为0。失败以漏选为主。

不能用被剔除的区域数量声称排除机制发挥了重要作用。flower的正关联总质量
6.560841→6.560833，orchids 2.986280→2.986215；虽然区域数量182→167、
112→73，改变的质量极少。fortress原正关联质量仅0.001200，本轮全部取消；
排除机制也会移除原来有帮助的证据。

这与[此前架构归因](2026-10-08-architecture-attribution-results.md)一致：
负分支不是主要漏选原因，正确正支持下仍然存在成员恢复问题。本轮是固定当前
场和证据融合后的独立验证，不是首次发现这一问题。证据不足以推出空间距离
是唯一原因；此前乐观几何覆盖上界也不支持简单归因于硬半径。

下一项独立探索保留每条正射线的条件假设，分别控制公共空间中心与射线中心，
检验过早原型汇合的影响。它仍不等于v10源RGB/SAM正提示扩展；不能把这项
失败用新增损失、延长训练或更换负约束权重掩盖。

## 验证与执行记录

24项相关测试通过，最终接口另有两项复查通过。fern完整原始正负提示在复制场、
全新进程通过正式接口回放，selected、membership、response、retained_response
逐值完全一致。源路径Python审计的拦截探针有效，实际禁止访问为0。
覆盖范围只是一例，不是全部八例或OS级隔离。

保留两次执行失败：第一次在design完成前启动，未产生预测；第二次24份预测及
八例评分已完成，汇总程序错误读取iou而非foreground_iou。单独修复汇总器，
未重跑或改动预测/评分。执行的汇总器原文按结果收据SHA保存，后续通用汇总器
不能冒充当时原文。证据在实验根目录validation/reporting及logs。

本轮保持旧120来源以隔离函数变化；另补齐的243合法来源仍有分辨率和生成契约
差异，尚未在这组实验引入。不能宣称完整同预算v10能力参照、全五项统一版本
或NVOS性能恢复。v10响应参考86.5134%还存在提示输入和运行时契约差异。
