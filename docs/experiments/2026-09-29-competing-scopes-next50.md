# next50：竞争范围假设与旧语义场盲区

本轮按专家建议聚焦范围证据，不改几何、编码器、语义分支或评估协议。所有结果是反复使用的LERF四场开发评估，不是独立最终测试。没有新增测试或审计框架。

## 方法

原next48解码器将每个源视角的检测范围固定，再学习一个共享的高斯成员集合。本轮保留两种范围解释：原检测范围、包含检测且原生查询相似度不低于相交候选的区域范围。多个实例按文本union任务取并集；这并未解决实例间独立身份，也不是完整的整体/部件层次模型。

- `latent`：两个经原场冲突资格约束的BCE+overlap能量，以等先验、温度0.1的soft-min组合。
- `hard`：选择两个能量较低者。仍由统一三维成员度耦合所有源视角；没有按GT挑候选。
- `crossview`：先把其他源视角正负证据通过固定可见性算子传回当前视角，在候选扩展区域累计支持与反对，为两个假设给出先验权重。排除当前视角本身的投票，概率限于0.05–0.95，其余优化不变。
- `corroborated`：独立机制对照，不使用范围混合。解除原场对正监督的一票否决：检测正例在其他源视角投影支持超过0.5时，也可进入解码，并撤销相应冲突负例。其余仍是next48单范围目标。

soft-min组合的是归一化部分标签能量，并非经过校准的完整性似然；不同假设的已知区域不同，不能把后验解释成真实对象概率。交叉视角先验使用同一批源图/教师，排除自投票不等于独立测试，更不保证几何对应正确。所有方法都读取额外源候选/描述符缓存；不是仅部署紧凑场。

所有方法冻结next44语义输出，只更新独立`selection_scores`。每查询120步，原高斯载体、源图和评估阈值不变。未使用目标RGB或GT构造预测。GT仅用于冻结评估后的开发分析。未按查询、场景拼接赢家。

最终数值见本报告末尾和 `output/scope_hypotheses_next50/summary.json`。对照next48：2D IoU53.9139/AP71.2115，实际集合投影IoU43.5225。上轮可靠性候选43.6784。集合投影分数使用二维GT，不是物理三维GT。

## 科研结论边界

多范围优化只解决“怎样允许不同范围竞争”，并没有创造可靠的身份、完整性证据。尤其某个查询若旧场和检测共同没有合格正例，换集合优化器无法救回；原场正例资格与跨视角对应必须分开诊断。

不能把局部查询改善当作所有场景提升，也不能把本轮对照包装成已经成立的CVPR贡献。真正需要证实的命题仍是：在不依赖目标图的条件下，如何可靠区分局部可见、整体/部件歧义与错误身份，并让新增正确证据进入场而不扩大错误范围。完整RGB+MoGe场重建、匹配强基线和独立泛化仍未完成。本轮未新增ScanNet、NVOS或UQIS成绩；默认主线不变。

代码：`scripts/research/decode_scope_hypotheses_next50.py`、`run_scope_hypotheses_next50.py`、`summarize_scope_hypotheses_next50.py`。运行日志、命令退出码、源候选、先验和预测均保存于 `output/scope_hypotheses_next50/`。

corroborated四场没有新增进入训练的查询。因此本轮没有证实它能解除实际盲区，也没有证实零分概念仅由旧场资格门控导致；其他视角检测/对应支持不足同样可能阻止更新。范围候选存在与可见合格正例存在不是同一回事。

当前最有力的结论是：多假设选择可改善个别范围，但既有候选证据不足以稳定改善困难场景。单纯soft-min或多视角投票不构成足够的论文贡献。下一步应在固定源视角上建立可信的身份/范围干预对照，先测正确范围写入后是否有效，再决定需要改进候选生成、关联还是几何承载。助手审阅须明确标为辅助标注，不冒充人工真值。
