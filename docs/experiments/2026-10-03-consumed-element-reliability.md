# 直接用最终元素召回训练源证据可靠性

2026-10-03。研究分支；唯一默认仍是`configs/pipeline/system_v5.json`。
本轮在上一轮有监督质量模型上落实两个方法变化：新增冻结区域语义证据，以及通过实际多视角融合训练可靠性。
已完成三个预留房间的30项公共入口评价（首批27项＋随后3项固定权重对照），以及3项明确隔离的标签诊断。
**结论：监督链已接通，训练拟合有提升；自动新房间收益不足，正负双头没有胜过同总量共享权重，不升级默认。**

## 需要解决的问题

上一轮的监督只要求两个输出接近每张掩码的precision/recall。不同范围错误对最终三维元素的影响却不相同：
一个错误可能被其他视角纠正，另一个可能压过地图中唯一正确的证据。平均质量误差小，不保证元素选择准确。
另外，原十个输入量主要描述检测置信度、范围大小及地图响应，没有读取完整掩码区域的独立语义判断。

这不是把“有监督融合”当作新概念。[GLFS/ICRA2024](https://motion.cs.illinois.edu/papers/ICRA2024_Marques_OverconfidenceSemanticMapping.pdf)
已经直接讨论二维校准不保证融合后三维校准，并联合学习融合、权重和校准。
[DeepViewAgg/CVPR2022](https://arxiv.org/abs/2204.07548)也研究可学习的多视角特征聚合。
本项目需要证明的是：在保持原生query空间、冻结几何及正/负/未知证据区分的条件下，
对实际元素决策的训练能否提供可迁移的净收益。实现一个可微权重器本身不足以支撑CVPR贡献。

## 已实现的完整路径

原生区域地图与冻结相机/几何 → 每视图正、负、未知范围 → 两个可靠性权重 → 原有可见性归一化融合 → 元素类别分数。

1. **独立区域语义输入。** 同一个冻结Mask-Adapter对检测范围的类别并集编码，保留原生CLIP空间。
   取当前query响应、最强竞争类别响应、完整菜单熵及两者对数差，形成四个额外统计量。
   它们不是新增真值，也不是768维原始embedding进入学习器；学习器仍不含类别编号或场景编号参数。
   完整19类菜单先计算，再支持运行时query分批，避免分批改变竞争语义。
2. **最终元素监督。** 固定线性投影和源掩码，预计算每个视图对元素的正/负分子及分母贡献。
   训练权重通过同一融合式影响实际元素分数；全部932源图和全部元素均保留，无源图或训练点上限。
   点真值按评价器的“GT顶点到最近元素”方向转移，用计数保留每个顶点的等权贡献。
   19类损失为0.5×类别均衡CE＋0.5×soft IoU，另保留0.1×质量BCE及0.001权重正则。
   未观测元素保持void，并留在IoU漏检分母中。15/10类仅评价，没有额外调参。
3. **权重含义修正。** 质量回归模型仍可解释为预计纯度/可见召回；经过元素损失训练后，输出是正负证据权重，
   不再声称它们是校准的precision/recall。地图、query编码器、几何及0.1先验强度不变。

使用一个真实训练房间的37源视图进行完整数值回放：编译训练算子与部署算子实际元素类别差异为0，
最大概率误差约9.995e-7、平均约9.32e-9；可微权重梯度有限。该检查是实际训练/部署等价性核验，未增加测试框架。

## 固定划分与对照

拟合仅使用旧九个官方训练房间，沿用上一轮监督条件；它们的结果不能称为独立验证。
上一轮0050_02、0231_01、0412_00已经打开，仍只作为开发数据。
本轮在设计时固定另一组官方验证房间：**scene0575_00、scene0591_02、scene0599_02**。
分别147/117/124张位姿有限的已导出stride20 RGB，共388张，全部使用；未使用这些房间的标签拟合或选模型。
这是本轮机制预留的验证，不能据目录新前缀推定项目从未接触这些数据，也不是封存最终test。
输入轨道仍是提供的无标签网格，不与RGB＋MoGe轨道混算。

固定比较：原SigLIP地图投票、Mask-Adapter地图投票、十统计量质量模型、十四统计量质量模型、
十统计量元素训练模型、十四统计量元素训练模型、后者的同总证据质量共享权重对照。
所有模型均在同一冻结学习区域地图、相机、源检测和总原生证据预算上比较。
线性模型采用原质量BCE初始化，再固定Adam0.03训练60轮，无验证选择。

训练集显示线性模型拟合增益不足1个百分点后，在打开本轮验证结果之前新增唯一容量对照：
14→32(SiLU)→2，共546参数；质量初始化LBFGS100，元素训练固定Adam0.003、60轮。
同时评价它的质量初始化和元素训练版本，避免把增加容量与下游目标混为一个收益。
设计修订理由和未读验证状态记录于`output/element_retrieval_reliability/design.json`，没有验证调参。

## 此轮进一步分清的两个实质问题

**区域教师不是在所有场景都更强。** 地图单独19类平均52.535175→57.254767，但0575为65.312667→56.723418，
下降8.589249个百分点；0591/0599分别提高6.619748/16.128277个百分点。
上轮三个房间均提高，本轮出现明确反例：简单全局替换教师会引入大范围地图身份退化。
可靠性头不能靠“地图认同它”作为独立的身份证据，因为地图在这个场景本身就可能错。
后一句是基于方法输入与结果的机制判断，不等于已证明每个错误的唯一来源。

**降低错误覆盖，不等于找全目标。** 在0599，相对原同地图投票，完整候选少破坏725个地图原本正确的点，
同时少纠正1,416个地图错误点。具体window：IoU75.853846→64.940991；误检806→516，但漏检2,333→3,940。
这不是单纯阈值统计问题，而是实际选取范围变窄、正确元素被排除。共享权重下该类回到75.808439%。
一个视图/类别只用两个标量，仍无法分别处理同一范围内部的错误身份、正确部件和遗漏实例。
这些结果提示局部可靠性是下一步应检验的限制；没有据此宣称局部模块必然有效。

两景提高、一景下降也说明，不能按房间替换为获胜分支后拼接总成绩。
完整错误计数和逐类IoU在`outcomes.json`，它只读取已经固定的预测，未产生新训练标签或推理规则。

## 单独的标签诊断，不计入方法结果

保持同一地图、掩码、投影及0.1先验，将预测权重替换为标注测得的mask precision/visible recall：
19/15/10为**64.806771/65.230849/71.636848%**；19类逐景64.676632/58.881156/70.862526。
这是使用评价标签构造预测的诊断，不是自动模型、独立成绩或理论上界。
相对同地图投票仍有2.967071个百分点19类空间，说明质量估计并非已经解决；同时不能用上一组三景约8.4个百分点的诊断增益外推所有房间。
所有模型文件的内容在评价前后保持一致。标签诊断输出只在`label_using_diagnosis/`，无部署配置读取。

## 成本、论文结论与下一阶段边界

额外区域身份证据在388源图上编码1,873个类别并集，沿用原掩码，无新增SAM调用。
三worker累计62.36秒（并行执行；不是整套重建时间）。配对保存的原池化/Mask-Adapter缓存共约24.05MiB；
实际候选只用其中Mask-Adapter部分。非线性权重checkpoint为5,311字节，**源图、冻结教师、几何和地图W/描述符另计**。
小权重器不等于紧凑系统；此轮没有完成整个系统的部署成本比较。

保留可微融合训练与原生语义输入的实现，作为后续共享机制基础；**不升级v5，不延长同一种全视图权重器的扫参**。
下一阶段集中一个问题：在原生区域/实际可见元素层面，区分可靠身份、可确认范围和未知范围，
使“减少误检”和“保住正确补全”可以分别发生。先在训练房间确认局部证据确实能解决本轮window式冲突，
再固定一个候选，用其他预留房间检验；不能把当前已打开的三个房间继续称为独立新数据。

LERF2D/选取投影、NVOS本轮没有改动或新增实验，不把原分数填成新机制的跨任务证明。
UQIS继续暂停；四query标注精度、紧凑多教师场、统一公开SOTA协议以及足够独立场景的论文证据仍未完成。
本轮是明确的机制排除与训练链补齐，**尚未实现用户要求的大幅性能提升，也不足以支持CVPR级贡献成立**。

## 复现与主要实现

数据根目录：`output/element_retrieval_reliability/`。

```bash
PYTHONPATH=. python scripts/research/prepare_independent_scannet_sources.py --root output/element_retrieval_reliability --scenes scene0575_00 scene0591_02 scene0599_02
PYTHONPATH=. python scripts/research/run_independent_scannet_build.py --root output/element_retrieval_reliability --scenes scene0575_00 scene0591_02 scene0599_02
PYTHONPATH=. python scripts/research/compile_element_reliability_training.py
PYTHONPATH=. python scripts/research/fit_element_reliability.py
PYTHONPATH=. python scripts/research/fit_element_reliability.py --native
PYTHONPATH=. python scripts/research/fit_element_reliability.py --native --hidden 32
PYTHONPATH=. python scripts/research/evaluate_element_reliability.py
```

Python环境使用`/root/miniconda3/envs/cybersim_agent/bin/python`；重建runner内部调用独立SAM环境。
训练数据编译支持分片，实际使用三个CPU分片；新房间自动区域使用六GPU，两个线性模型并行训练。
公开推理入口仍为`python -m radio_gs.pipeline`，评价仍由`evaluate_scannet_runtime.py --point-only`执行。
首批27项预测全部落盘后才由评价阶段读取新房间标签。随后为最强容量候选补齐3项同总量共享权重对照；
该补充发生在看过首批结果之后，沿用完全相同的冻结checkpoint，无重新拟合或参数选择。无逐场景择优或历史结果回填。

核心代码：`supervised_scope_reliability.py`、`element_reliability_fit.py`、`streamed_category_vote.py`。
新区域语义为按query生成的源辅助资产，不计作离线紧凑地图；包括源图、模型和缓存的实际成本需单列。
该类别分区机制不直接用于LERF整体/部件或NVOS参考实例，尚不证明四query统一泛化、紧凑蒸馏或公开SOTA。
