# 多候选范围对照与校准前向合约修复

本轮没有新增大幅性能提升。完成两组候选合并对照，拒绝用它们替换当前单候选路径；另修复已有阈值校准与推理的运算顺序不一致。前向一致校准作为正确性修复保留，新的文本开发 checkpoint 为 `exact_render_query_threshold96`，结果基本不变，旧模型继续作控制。

## 真实结果与取舍

同一完整文本 LERF 开发协议，56 / 71 个观测、宽 480、完整目标分母、全场渲染。数值为 IoU / AP（%）。

| 方法 | figurines | ramen |
|---|---:|---:|
| 上轮：单候选，范围内外分别保留原生排序 | 43.50 / 62.93 | 28.42 / 42.81 |
| 仅要求原生支持 IoU 增长的多候选并集 | 41.22 / 62.61 | 28.36 / 42.63 |
| 同时要求原生支持精确率不下降的并集 | 43.29 / 63.64 | 28.78 / 43.00 |
| **保留单候选，修正校准前向运算顺序** | **43.52 / 62.91** | **28.42 / 42.81** |

第二个并集版本有混合收益：AP 两场景提高，ramen IoU 小幅提高，figurines IoU 下降。未选每场景赢家，未宣传为一致提升。修正校准的微小差异也不包装为性能突破。

## 1. 检验“只能选一个区域是否限制覆盖”

固定原几何、所有模型张量、概念门控、候选集合和 query。只对门控拒绝的结构补全查询，将单个最高交并比候选替换为贪心并集：

- 从空集开始，首个候选就是原来的最佳单候选。
- 每次只添加使并集与**已观察元素上的原生正响应**的 IoU 严格提高的候选；没有提高时停止。
- 不预设合并数量，不用目标标签挑候选；原生支持来自原模型既有 query 阈值。
- 仍保留原生排序在最终 membership 内、外各自的顺序。原门控接受的概念范围不变。
- 第二个版本额外要求每次合并不降低相对原生正响应的精确率；没有新增经验权重或评估阈值。

这些条件保证的是对原生支持集合的自洽性，不是实际对象正确性。部署仍只有一个逐元素场；但查询时临时解码 N×R 候选 membership，增加内存与计算，不能声称已解决大场景扩展性。

## 2. 最重要的反例：代理目标变好，真实目标却变差

| 查询 | 原生支持 IoU：单→并 | 原生支持覆盖率：单→并 | 真实 IoU：单→并 |
|---|---:|---:|---:|
| figurines / toy cat statue | 37.1→58.2% | 40.0→88.3% | 58.2→18.9% |
| figurines / jake | 25.0→32.3% | 48.0→75.3% | 15.5→10.0% |
| figurines / red toy chair | 46.5→62.2% | 56.2→87.3% | 23.3→16.9% |

toy cat statue 的原生支持精确率从 83.6% 降到 63.1%，说明增加覆盖的同时引入大量缺乏当前 query 支持的元素。精确率约束能抑制这种扩张，但不够解决所有问题：jake 相对原生支持的精确率也从 34.3% 提高到 36.1%，真实 IoU 仍下降。

所以，**不能继续把未验证的原生正响应当作完整对象真值来优化范围**。这些实测不证明单候选永远足够，也不证明多实例不需要并集；它们否定的是“只优化当前原生二值支持的重叠就能可靠恢复完整对象”这一假设。

图像和注册提示路径没有修改，两个并集版本均完成三类参考评估，图像/提示逐观测保持一致。

## 3. 已修复的前向合约不一致

追查原生正响应来源时，确认旧 `fit_full_source_query_threshold.py` 使用的是：

`先渲染 native cosine → 在像素均值上选择阈值`。

实际检索则是：

`各元素 sigmoid(scale × (cosine − query_threshold)) → 渲染 → observed mass 归一化 → 0.5 判定`。

非线性 sigmoid 与混合渲染不能交换。旧报告已注明这个近似，但后续模型一直继承了这套校准。本轮新增 `fit_exact_render_query_threshold.py` 按实际推理顺序拟合，旧脚本与结果保留为历史对照。

受控修复保持原来的源查询和完整教师 mask 集合、置信度接纳规则、固定场、温度、源视角和校准分辨率。只有阈值拟合的前向目标改变：

1. 在已观察元素原生余弦的范围内，每个 query 用 17 点阈值网格，实际先 sigmoid 再用 gsplat 渲染。
2. 使用与部署一致的 observed mass 归一化和可见性规则，对完整源教师 mask 计算交并，不丢弃无几何支持的目标像素。
3. 做三轮由粗到细的搜索，每轮包含上一轮最佳阈值，保证源侧已评估的最佳 IoU 不下降。它是近似数值搜索，不声称穷举全局最优。
4. 与旧方案一样，用源查询的留一概念 MSE 选择 ridge 系数，拟合从 query 到阈值的函数。目标评估查询、目标 RGB 和标注都没有参与。

源侧直接阈值校准：

| 场景 | 源查询数 | 旧阈值经实际部署前向的源 IoU | 修正后源 IoU | 单查询阈值最大变化 |
|---|---:|---:|---:|---:|
| figurines | 28 | 36.987% | 37.128% | 0.00333 |
| ramen | 15 | 45.359% | 45.389% | 0.00210 |

这些源数值是在各 query 独立拟合阈值后的诊断，不是 ridge 泛化或独立 test 成绩。最终真实指标基本不变，表明当前校准运算顺序误差的量级有限；不能把它当作巨大低分的主要解释。改动只涉及三个文本阈值张量，原生特征、教师解码器、范围头、几何和图像/提示参数保持不变。

## 4. 从系统层面收窄剩余问题

上轮证明当前 64D 压缩的平均损失较小，且范围头曾严重破坏原生排序；本轮进一步证明补全目标本身存在可靠性缺口。现在不能再把剩余失败统一归为“更多候选”“更多维度”或“一个阈值实现错误”。

优先任务应是源证据与查询对象对应：原生高分元素为什么包含其他对象、哪些细粒度语义在源证据融合之前/之后已经丢失，以及怎样用独立源视角的正负范围证据验证对应。需要在已验证的对应上学习范围，而不是继续提高对一个不可靠二值支持集合的拟合。

本轮校准修复保留为正确性改进；两个并集版本仅作研究对照，不替换单候选主线。未新增 ScanNet OVS、NVOS 或 SAM 2D prompt 完整成绩，未证明超过历史正常版本，所有结果仍为反复使用的 LERF 开发评估。
