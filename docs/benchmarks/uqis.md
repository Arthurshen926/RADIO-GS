# UQIS：固定地图上的四模态实例召回

UQIS服务于RADIO-GS的统一地图主张：同一场景先建图，之后分别接收text、image、2D正点、3D正点，返回同一官方mesh上的目标实例分数。查询时不读取源照片。它补充LERF、ScanNet OVS和NVOS，不能替代这些不同任务的结果。

当前维护实现为`radio_gs.benchmarks.uqis`。旧v0.1/v0.2及其成绩保留在历史分支和output目录。
v0.3完整四模态方法实验已完成；v0.3.1在相同参考帧内修正一条穿过目标mesh缺口的2D提示。
当前交付候选为`output/scannet_uqis_9_v0_3_1_candidate`。所有版本仍是已打开的开发集。

16.387／34.876／42.090／41.524%。同目标四种查询同时IoU>=0.5为7/67，场景宏平均仅10.384%。

这些只做一致性诊断：四种输入可能一致认错，因此必须与各自真实IoU、四类共同成功率一起解读。

后者明确列出目标数和场景数，只用于分辨“对象选错”与“对象找不全”，不得替代全量主指标。

## 输入与目标

| 模态 | 方法输入 |
|---|---|
| text | 场景ID、自然语言实例指代 |
| image | 场景ID、224×224 RGB参考裁剪；不带裁剪坐标、源帧和相机 |
| point_2d | 场景ID、相机内外参、栅格尺寸、一个正像素；不带RGB、深度、SAM或目标mask |
| point_3d | 场景ID、一个世界坐标正点 |

建图可使用明确轨道中的合法RGB/RGB-D/几何；同轨比较方法须获得公平输入。源照片不得成为查询时的隐藏依赖。image query自己的裁剪是合法query，不等于开放源图库。

本次候选明确为官方mesh／RGB-D辅助几何轨道，方法可读取无实例标签的mesh坐标作为输出域。官方mesh由完整扫描生成，不能宣称它也排除了查询视图的几何贡献；视图排除约束的是特征建图观测。RGB+MoGe重建轨道需要另外固定几何输入和传递规则，不能与该轨道混算。

目标范围严格使用官方ScanNet实例标注。一些标注本身包含成组的书、柜子或毛巾，不能描述为全部都是一个物理原子对象。v0.3保留原9场景67个实例，不根据模型分数筛选。

尚未覆盖：独立部件真值、同类所有实例联合查询、多轮正负交互。这些应作为后续独立轨道，不能伪造标签填满任务矩阵。

## v0.3构造

- 从可读`.sens`和官方mesh实例标签生成查询，不依赖不可读的旧2D标注ZIP。
- 使用原始RGB-D内参，不把RGB简单缩放后当成深度相机图像。
- 候选点必须在正确实例5cm范围内，且位于目标掩码内部、远离栅格边界，同时可投影到RGB有效区域。
- 2D坐标使用原生深度相机栅格；深度只在构建时反投影生成配对3D点，不向方法提供。栅格和内参随query明确给出。
- 图像从对应RGB相机按正确配准裁剪；方形裁剪保留纵横比例。源图不做去模糊、生成式补全或语义修改。
- 选帧同时考虑可靠可见范围、目标内部清晰度、曝光和目标占比；不使用方法输出或评价标签统计选赢家。所有实例使用同一规则。
- 每20帧扫描候选是当前明确的构造计算预算，不是建图源图上限。取消每场景最多3个查询帧的限制；优先挑清晰参考，再联合调整选帧以保留建图可见性。
- 新查询帧的±5邻帧、10cm/8度内近姿态视图统一排除；保留旧条件：至少5个采样建图帧可见目标，目标表面覆盖至少70%。可见性按每20帧、深度步长4、8cm匹配统计；它不是5个独立视角基线或无误对应的证明。
- 覆盖按合法采样深度表面与官方目标顶点5cm内距离统计。该支持率衡量是否存在可用观测，不代表重建几何已经同等精确。
- 文本保留原始Nr3D表达，全部67条具有助手逐条检查的能力标签。标签可重叠，不声称已获得独立人工身份／唯一性认证。
- 新版本及query内容参与不透明ID生成；不按旧ID复用预测。

图像质量选择规则不能证明每个目标都可唯一辨认。强反光、相似外观和原始实例标注歧义需保留为明确难点；不得在看到模型分数后删除难例。

v0.3.1补充真正的三角面前表面检查。原版66/67通过，另一个lamp点击指向RGB-D目标但穿过mesh缺口。
在同一参考帧内，按可靠内部距离选择3×3邻域均首先命中目标且与深度一致的像素；不读取方法输出。
新包67/67中心射线通过。修正只改变这一条2D提示，3D点仍保持原值：四模态需同一实例，允许不同表面点。
参考帧和排除集合未变，因此已按v0.3重建的合法地图可用；全部预测须重新生成，不能继承改变的查询答案。
未改query保留原ID及来源版本，包级版本由`release.json`指定。

来源补查：67条文本全部匹配Nr3D原文、目标编号和类别，原始听者记录均为正确。
逐条证据在候选目录`language_provenance.json`。这支持原始指代任务的可靠性，
不替代UQIS当前输入条件下的独立唯一性核验。后续导出同时保留原始文本标注ID。

已完成v0.3.1全量模型运行：同一地图的文本／图像／2D点／3D点AP为
19.642／25.868／52.745／52.359%，采用原生语义与点锚点共归属读出。
配置`configs/pipeline/uqis_map_only_v031.json`；三种完整对照结果在
`output/uqis_map_only_v031`。它证明四模态执行与真实3D评测闭环，尚未证明高性能或紧凑场主张。

## 使用

```bash
python -m radio_gs.benchmarks.uqis.construct \
  --legacy-root output/scannet_uqis_9_v0_1 \
  --text-profile output/scannet_uqis_9_v0_2_candidate/text_profile_v1.json \
  --config configs/benchmarks/uqis_v0_3_construction.json \
  --output output/scannet_uqis_9_v0_3_candidate/mapping_supported --workers 3

python -m radio_gs.benchmarks.uqis.package \
  --legacy-root output/scannet_uqis_9_v0_1 \
  --text-profile output/scannet_uqis_9_v0_2_candidate/text_profile_v1.json \
  --text-review configs/benchmarks/uqis_v0_3_text_review.json \
  --construction output/scannet_uqis_9_v0_3_candidate/mapping_supported \
  --visual-review output/scannet_uqis_9_v0_3_candidate/reference_visual_review.json \
  --output output/scannet_uqis_9_v0_3_candidate/release_final

python -m radio_gs.benchmarks.uqis.stage \
  --package output/scannet_uqis_9_v0_3_1_candidate \
  --modality point_2d --query-id QUERY_ID --output output/one_uqis_query

python -m radio_gs.benchmarks.uqis.evaluate \
  --package output/scannet_uqis_9_v0_3_1_candidate \
  --predictions output/my_uqis_predictions --output output/my_uqis_result.json
```

包内`method/`只有query和官方mesh坐标域；`mapping/`给建图阶段合法帧清单；`evaluator/`包含配对、实例标签和私有构造信息。方法查询进程只拿一次`stage`生成的目录与自己的冻结地图，不能拿整个包。

`release_final`保留为v0.3成绩对应包；当前为上方v0.3.1目录。此前`construction`、`registered`、`release`为构造过程中的中间结果，不能代替最终包。可视审阅文件逐条绑定图片哈希；它记录助手可见的困难，不是独立人工真值。新生成的图片需要重新审阅，不能套用旧结论；本次未改变参考裁剪。

参考帧改变后必须依据新排除集合重建地图。旧地图可能看过新查询图，不能直接重用它们并把结果叫v0.3严格成绩。

## 评价与科研报告

每个query提交`<query_id>.npy`，内容是官方mesh同序的`float32[V]`、范围[0,1]。相似度需要使用预先固定的转换；不能用该query的GT选阈值。

方法还可通过`--selections DIR`提交每个query的`bool[V]`实际元素集合，必须完整覆盖所声明的查询。
该扩展不改变v0.3.1输入、标签和原有AP：评价器直接计算集合IoU／purity／coverage，单列为
`explicit_selection`，不根据GT或oracle分数替方法选阈值。没有集合输出的方法仍可参加排序对照；
不能把其未校准分数的0.5诊断与另一方法的集合IoU差值直接宣称为算法增益。
同样，排序AP提高不意味着已解决完整对象取出。公平集合对照需双方明确提供各自选出的元素。
完整四模态集合提交还报告：同一目标的最低IoU，以及四种查询**同时**达到IoU0.25／0.5的比例，
按场景宏平均。这是评价已提交集合的质量门槛，不是用GT给预测分数挑阈值。

单模态对照可用`--modalities text`等明确声明能力，只提交该模态全部目标的预测；不会获得四模态汇总分，也不会把缺失模态记成0后混算。

- 主报告是同一67目标上四模态各自的scene-macro AP，附scene bootstrap区间。
- 等权四模态AP平均是补充汇总，不取代分项。
- `paired_query_robustness`补充报告每个目标四种AP的最小值与几何平均，再按场景平均。
  配对仅存在于评价器中，不给方法。这个统计能揭示同一目标的某一模态失败；它不是新的mask准确率，
  不改变原四项AP和67目标主队列。单模态方法不获得该配对汇总。
- 按实际空间关系、比较、否定等文本标签分层，标签重叠，不将它们误称互斥难度层。
- 审阅标记的成组官方实例在四种模态下分别给出诊断，避免把一个物理对象与成组标注的范围差异全归为模型错误；参考图困难分组用于图像查询诊断。两种分组均不改变67目标主分数，也不是筛选高分子集。
- 固定0.5的IoU、purity、coverage保留为未校准诊断，直到在独立开发场景固定读出／校准。oracle IoU始终只是诊断。
- 同时报告实际地图数量、各模态依赖、存储、建图和查询成本。多个独立场可以是合法对照，但不能支撑单一统一场主张。
- 输出保留逐query结果，便于区分身份混淆、范围漏召回和同类干扰；主统计不删除困难目标。
- 当前9个场景已经被历史开发打开。需要另外建立校准与最终验证场景，才能支持独立泛化结论。

## 接下来仍需完成

1. 处理助手视觉核验指出的模糊、反光、背景占比和身份歧义，核验文本在没有源视图上下文时是否唯一可解。当前困难目标全部保留；助手审阅不能代替独立身份认证。
2. 建立不同场景的校准集，固定实际集合读出；不能在这9景调阈值。
3. 同地图四模态mesh输出已完整跑通；继续补齐文本实例关系、图像身份和可靠范围补全能力。v8的text／image AP约26.60%／44.03%，四类共同成功率仍低，不能称为高性能统一召回。
4. 当前高容量地图使用原生区域语义、局部外观、归属和可见性，九景合计2852.81MiB；另有原SigLIP共享7.49GB编码器及DINO权重330.33MiB。继续验证紧凑学生，不能只报告场景张量成本。
5. 在基础实例轨道稳定后，增加有独立真值支持的部件和交互扩展。

## 与其他benchmark共用的架构

共同架构由[ADR0012](../adr/0012-common-observation-architecture-and-query-contracts.md)固定：
冻结几何与合法观测 → 原生教师身份响应 → 任务所需的范围证据 → 元素或渲染读出。
`python -m radio_gs.pipeline.cohort`统一维护LERF的语义／选取投影、NVOS、ScanNet OVS及UQIS。
UQIS在配方中显式为`map-only`，其他任务按原协议声明输入；共用代码不扩大数据权限。
类别全集竞争、类别集合、单实例三种目标允许不同数学读出，不从benchmark名称推断某个具体目标。
